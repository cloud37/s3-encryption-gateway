## 1. Context & Current State

AWS Signature Version 2 presigned requests carry the authentication value in
the URL query parameter `Signature`; the gateway recognizes the query form as
`AWSAccessKeyId + Signature` in `internal/api/credentials.go:117-128` and reads
the signature during validation in `internal/api/auth.go:190-247`. AWS
Signature Version 4 instead uses `X-Amz-Signature`. Both values are bearer-like
authentication material and must not be persisted in telemetry [1][3].

Access logging already has a package-local `redactQueryString` helper in
`internal/middleware/logging.go:14-44`. It parses with `url.ParseQuery`, matches
decoded keys case-insensitively, replaces matching values, and returns the
fail-closed sentinel `[REDACTED]` on malformed input. Its sensitive-key list at
`internal/middleware/logging.go:14-21` includes `x-amz-signature`, but not the
SigV2 key `Signature`; consequently `Signature=<secret>` remains in access-log
query output. `createLogEntry` invokes the helper at
`internal/middleware/logging.go:126-138`, and the default, JSON, and CLF writers
all emit that resulting query at `internal/middleware/logging.go:168-220`.

Tracing constructs `http.url` without a query at
`internal/middleware/tracing.go:24-39`, but separately records `http.query` at
`internal/middleware/tracing.go:52-59`. With broad `redactSensitive=true`, the
whole query becomes `[REDACTED]`; with `redactSensitive=false`, the raw query is
recorded. The setting is explicitly optional in `internal/config/config.go:670-680`
and documented in `docs/DEVELOPMENT_GUIDE.md:343-376`. Thus disabling broad
redaction currently exposes both SigV2 and SigV4 presigned signatures in
traces, even though benign query fields are operationally useful.

The existing query test covers empty, benign, SigV4, and malformed inputs at
`internal/middleware/logging_test.go:226-250`, but does not cover SigV2,
case variants, URL-decoded keys, duplicates, or each access-log format. The
tracing tests verify whole-query redaction enabled and benign raw-query output
disabled at `internal/middleware/tracing_test.go:102-151`, but do not assert
mandatory signature-only redaction in either mode. The objective is one shared
redaction boundary used by access logs and tracing, without mutating the
request or changing authentication behavior.

## 2. Design Goals & Non-Goals

### Goals

1. **Mandatory signature redaction** — always replace every value belonging to
   a case-insensitive, URL-decoded `Signature` or `X-Amz-Signature` key with
   `[REDACTED]` before access-log or trace emission.
2. **Duplicate-safe behavior** — redact all values when either sensitive key
   occurs more than once, including mixed key casing.
3. **Fail-closed parsing** — return exactly `[REDACTED]` for any non-empty query
   that `url.ParseQuery` reports as malformed [2].
4. **Preserve diagnostics** — retain benign keys and all their values, subject
   only to canonical `url.Values.Encode` ordering and escaping.
5. **Shared policy** — expose one `middleware.RedactSensitiveQuery` function
   and use it in both access logging and tracing.
6. **Configuration independence** — preserve whole-query redaction when broad
   tracing redaction is enabled, while still redacting signatures when it is
   disabled.
7. **Authentication invariance** — do not mutate `r.URL.RawQuery`, request
   headers, routing state, or any auth function input or output.

### Non-Goals

1. **SigV2 authentication changes** — acceptance, expiry, canonicalization,
   and HMAC verification remain owned by `ValidateSignatureV2`; this issue is
   telemetry-only.
2. **Additional mandatory query keys** — the existing broader access-log list
   remains intact, but expanding mandatory cross-channel redaction beyond
   `Signature` and `X-Amz-Signature` is out of scope to avoid hiding benign
   diagnostics unexpectedly.
3. **Header or body redaction changes** — existing configurable header handling
   and payload behavior are unaffected.
4. **Configuration schema changes** — no new YAML, environment variable, or
   Helm value is needed because signature redaction is unconditional.
5. **Raw query byte preservation in telemetry** — canonical re-encoding is
   acceptable; authentication continues to consume the untouched request.

## 3. Target Interface / Semantics / Behaviour

Add the following shared package API:

```go
// RedactSensitiveQuery returns a telemetry-safe encoding of rawQuery.
// It never mutates a request or caller-owned value.
func RedactSensitiveQuery(rawQuery string) string
```

The implementation uses `url.ParseQuery`, iterates every decoded map key,
compares with `strings.EqualFold`, replaces the entire value slice for every
matched key with `[]string{"[REDACTED]"}`, and returns `values.Encode()`.
Replacing the slice rather than calling `Set` explicitly guarantees that all
duplicate secret values disappear. A single exported function is appropriate
because logging and tracing are separate middleware implementations but must
share an identical security policy [3].

| Input class | Required output |
|---|---|
| Empty string | Empty string |
| `Signature=sigv2` | `Signature=%5BREDACTED%5D` |
| `X-Amz-Signature=sigv4` | `X-Amz-Signature=%5BREDACTED%5D` |
| Case variant, such as `sIgNaTuRe=sigv2` | Same decoded key, encoded with value `[REDACTED]` |
| URL-encoded key, such as `%53ignature=sigv2` | Decoded key `Signature`, encoded with value `[REDACTED]` |
| Duplicate sensitive key values | Every original value removed; one redaction marker for that decoded map key |
| Both signature key families | Both values redacted independently |
| Sensitive plus benign keys | Sensitive values redacted; benign keys and duplicate benign values preserved |
| Any malformed non-empty query, such as `prefix=%ZZ` | Exactly `[REDACTED]` |

`url.ParseQuery` is required instead of `URL.Query` because the latter silently
discards malformed pairs; fail-closed behavior depends on observing the parse
error [2]. Canonical output ordering is intentionally delegated to
`url.Values.Encode`.

Access-log behavior is unconditional for all three existing formats:

| Format | Emission path | Required behavior |
|---|---|---|
| `default` | `query` structured field | Use `RedactSensitiveQuery` output |
| `json` | `LogEntry.Query` in embedded JSON | Use `RedactSensitiveQuery` output |
| `clf` | Request target suffix | Use `RedactSensitiveQuery` output |

Tracing behavior is:

| `redactSensitive` | Non-empty `http.query` attribute |
|---|---|
| `true` | Exactly `[REDACTED]`, preserving the existing broad-redaction contract |
| `false` | `RedactSensitiveQuery(r.URL.RawQuery)`; benign fields remain visible |

In every mode, `http.url` remains query-free and the middleware passes the
original request to downstream authentication. No call to
`ValidateSignatureV2`, `ValidateSignatureV4`, `IsSignatureV2Request`, or
`IsSignatureV4Request` changes.

## 4. Work Breakdown

### Phase A — Shared query redaction policy

- A1. **New:** `internal/middleware/query_redaction.go`. Move the existing
  sensitive query policy out of `logging.go`, export
  `func RedactSensitiveQuery(rawQuery string) string`, retain existing keys,
  add `signature`, and match decoded keys with `strings.EqualFold`. Preserve
  empty-input and malformed-input behavior exactly.
- A2. **New:** `internal/middleware/query_redaction_test.go`. Add table-driven
  `TestRedactSensitiveQuery` covering empty, benign duplicates, canonical
  SigV2, canonical SigV4, mixed-case names, URL-encoded names, duplicate
  sensitive values, both signature families together, mixed benign/sensitive
  values, and malformed percent encoding. Add
  `TestRedactSensitiveQuery_DoesNotMutateRawQuery` to make the no-mutation
  contract explicit.

Intended helper shape:

```go
func RedactSensitiveQuery(rawQuery string) string {
    if rawQuery == "" { return "" }
    values, err := url.ParseQuery(rawQuery)
    if err != nil { return "[REDACTED]" }
    for key := range values {
        if isSensitiveQueryKey(key) {
            values[key] = []string{"[REDACTED]"}
        }
    }
    return values.Encode()
}
```

### Phase B — Apply the policy at observability boundaries

- B1. **Edit:** `internal/middleware/logging.go`. Remove the local
  `sensitiveQueryParams` and `redactQueryString` definitions and their now
  unused `net/url` import. Change `createLogEntry` to call
  `RedactSensitiveQuery(r.URL.RawQuery)`; leave `logDefault`, `logJSON`, and
  `logCLF` unchanged so all formats inherit the shared result.
- B2. **Edit:** `internal/middleware/tracing.go`. Keep the existing
  `[REDACTED]` branch for `redactSensitive=true`; change only the false branch

## 7. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| SigV2 key matching is case-sensitive or performed before URL decoding, allowing alternate spellings to leak. | Match decoded `url.ParseQuery` map keys with `strings.EqualFold`; test mixed-case and `%53ignature`. |
| Duplicate signature values survive because only the first value is replaced. | Replace the complete `[]string` value slice and assert no duplicate secret appears. |
| A malformed pair causes `ParseQuery` to return valid partial values that are then emitted. | Discard the entire parsed map whenever `err != nil` and return exactly `[REDACTED]`. |
| Broad tracing redaction disabled is incorrectly treated as permission to expose authentication material. | Route the disabled branch through `RedactSensitiveQuery`; test both boolean modes separately. |
| Redaction mutates `r.URL.RawQuery` before authentication, invalidating signatures or changing request classification. | Redact a string copy only; never assign to the request; retain auth regression tests and add downstream immutability tests. |
| Canonical re-encoding reorders telemetry query parameters and changes escaping. | Document this as intentional; assert values rather than original byte ordering. Authentication still sees original bytes. |
| Access-log writers diverge and one format bypasses redaction. | Redact once in `createLogEntry` and run the same leak assertions against default, JSON, and CLF. |
