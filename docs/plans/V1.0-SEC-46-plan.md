# V1.0-SEC-46 — Fail Closed When Multipart Routing State Is Missing — Implementation Plan

Status: Draft
Owner: Security / API / MPU
Priority: P1
Labels: `milestone:v1.0`, `area:security`, `area:api`, `area:mpu`

> Scope clarified relative to the tracker entry at
> `docs/issues/v1.0-issues.md`. This plan preserves creation-time routing while
> removing missing-state-as-plaintext from the secure default.

---

## 1. Context & Current State

`uploadStateEncrypted` maps `mpu.ErrUploadNotFound` to `(nil, false, nil)` and
documents that result as a plaintext MPU (`internal/api/handlers.go:148-177`).
UploadPart consequently enters its plaintext body path
(`internal/api/handlers.go:4018-4049,4137-4161`), Complete calls the backend
without encrypted manifest handling (`internal/api/handlers.go:4307-4387`), and
UploadPartCopy uses the same destination decision. Loss, eviction, expiry, or
operator deletion of one encrypted state key is thus interpreted as affirmative
evidence that ciphertext processing is unnecessary.

Creation persists Valkey state only when the live bucket policy encrypts MPUs
(`internal/api/handlers.go:3425-3441,3456-3508`). Plaintext uploads have no
durable mode record, so simply making every missing key an error would break
in-flight legacy plaintext MPUs. ADR 0009 deliberately supports policy opt-out
(`docs/adr/0009-encrypted-multipart-uploads.md:184-188`) while requiring policy
snapshot semantics. The safe forward design is to persist a mode record for
every new upload whenever Valkey is configured, use it as the sole routing
authority, and gate untracked legacy plaintext uploads behind an explicit,
default-off migration setting. A deployment with no state store and a policy
that permits plaintext retains the existing backend-native MPU path.

## 2. Design Goals & Non-Goals

### Goals
1. **Fail-closed absence** — configured state-store misses never imply plaintext by default.
2. **Creation-time mode** — both encrypted and plaintext uploads retain their original policy mode after policy reloads.
3. **Operation parity** — UploadPart, UploadPartCopy, Complete, and Abort use one lookup contract.
4. **Safe compatibility** — legacy untracked plaintext is available only through an explicit migration switch and warning.
5. **Lifecycle cleanup** — tracked plaintext state is removed after successful Complete or Abort.
6. **No false backend mutation** — `NoSuchUpload` is returned before part upload, copy, complete, manifest, or lifecycle backend calls.

### Non-Goals
1. Recovering encrypted DEKs after total Valkey loss; affected uploads must be aborted/recreated.
2. Discovering in-flight mode from mutable live bucket policy.
3. Changing completed MPU object format or encryption policy defaults.

## 3. Target Interface / Semantics / Behaviour

```go
type PolicySnapshot struct {
    EncryptMultipartUploads bool `json:"encrypt_mpu"`
}

func (h *Handler) uploadState(ctx context.Context, uploadID string) (*mpu.UploadState, error)
```

When a state store exists, CreateMultipartUpload writes a versioned
`UploadState` for both modes. Plaintext records carry identity, policy snapshot,
phase, revision, and creation time but no DEK, IV, binding, or KMS fields.
Encryption helpers must reject a record whose snapshot is plaintext.

| Store / record | Default behavior |
|---|---|
| no store and live policy permits plaintext | backend-native plaintext MPU |
| no store and live policy requires encryption | existing 503 misconfiguration guard |
| store has encrypted record | encrypted path from snapshot |
| store has plaintext record | plaintext path from snapshot |
| store returns transient error | 503 `ServiceUnavailable` |
| store returns `ErrUploadNotFound` | 404 `NoSuchUpload` before backend contact |
| missing record + explicit legacy option | plaintext compatibility path with warning/metric |

New configuration:
```yaml
multipart_state:
  allow_untracked_plaintext_uploads: false
```
Environment: `MPU_ALLOW_UNTRACKED_PLAINTEXT_UPLOADS`. Validation emits a
security warning when true. Rationale: explicit compatibility is auditable and
does not let state loss silently change confidentiality semantics [1].

## 4. Work Breakdown

### Phase A — Persist mode for every new upload
- A1. **Edit `internal/mpu/state.go`:** document that `UploadState` may be a
  plaintext routing record; validate crypto fields only when
  `PolicySnapshot.EncryptMultipartUploads` is true.
- A2. **Edit `internal/api/handlers.go`:** after backend Create succeeds, write
  either the existing encrypted state or a plaintext state with bucket/key,
  `CurrentStateVersion`, `UploadPhaseOpen`, revision 1, and policy snapshot
  false. If configured-store persistence fails, abort the backend MPU and return
  503 for either mode.
- A3. **Edit `internal/mpu/state_test.go`:** add
  `TestStateStore_PlaintextRoutingRecordRoundTrip` and
  `TestStateStore_PlaintextRoutingRecordRejectsCryptoOperations`.

### Phase B — Central fail-closed routing
- B1. **Edit `internal/config/config.go`:** add
  `MultipartStateConfig.AllowUntrackedPlaintextUploads`, default false, env
  loading, validation warning, and reload semantics.
- B2. **Edit `internal/api/handlers.go`:** replace `uploadStateEncrypted` with
  `uploadState`; do not require `keyManager` merely to read a plaintext record;
  map missing state to `NoSuchUpload` unless the compatibility option is true.
  Apply the helper to UploadPart, Complete, and Abort and delete tracked
  plaintext records only after successful backend terminal operations.
- B3. **Edit `internal/api/upload_part_copy.go`:** select destination mode only
  from `uploadState`; missing state returns `NoSuchUpload` before source reads or
  destination mutation.

> Phase B depends on the all-mode records from Phase A.

### Phase C — Tests, configuration surfaces, and docs
- C1. **Edit `internal/api/encrypted_mpu_handler_test.go`:** replace the old
  missing-state plaintext expectation with
  `TestUploadPart_MissingTrackedStateReturnsNoSuchUploadWithoutBackendCall` and
  add creation-time mode/policy-flip tests.
- C2. **Edit `internal/api/upload_part_copy_strategy_test.go` and
  `internal/api/sec38_complete_handler_test.go`:** add missing-state no-source-
  read/no-backend-call cases for copy and Complete.
- C3. **Edit `internal/config/config_test.go`:** test default false, env parsing,
  and warning when compatibility is enabled.
- C4. **Edit `config.yaml.example`, `helm/s3-encryption-gateway/values.yaml`,
  `values.schema.json`, `templates/deployment.yaml`, and Helm tests:** expose the
  option with default false and migration-only wording.
- C5. **Edit `docs/adr/0009-encrypted-multipart-uploads.md`, `SECURITY.md`,
  `README.md`, and `CHANGELOG.md`:** record all-mode routing state, data-loss
  behavior, and migration procedure.
- C6. **Edit `docs/issues/v1.0-issues.md`:** close SEC-46 after verification.

## 7. Risks & Mitigations
| Risk | Mitigation |
|---|---|
| Existing untracked plaintext MPUs stop working | Explicit migration option, startup warning, release note, and rollback/expiry procedure. |
| Plaintext tracking makes Valkey newly required | Only track when a store is configured; no-store plaintext deployments retain current behavior. |
| Plaintext record accidentally enters encryption | Validate crypto fields conditionally and make encryption helpers assert the encrypted snapshot. |
| Backend MPU survives state persistence failure | Abort immediately and never return its upload ID. |
| Terminal operations leak routing records | Delete plaintext records only after successful Complete/Abort and test both paths. |
