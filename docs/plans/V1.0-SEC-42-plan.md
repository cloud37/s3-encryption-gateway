# V1.0-SEC-42 — Bind Encrypted Objects to Bucket and Key — Implementation Plan

Status: Draft
Owner: Security / Crypto / API

> Scope clarified relative to the tracker entry in

> limitation into a versioned implementation and migration contract.
> V1.0-SEC-42 depends on V1.0-SEC-37 and MUST extend SEC-37's

## 1. Context & Current State

The crypto API currently receives `context.Context`, the payload reader, and a
mutable metadata map, but no separately trusted object identity:
`EncryptionEngine.Encrypt`, `Decrypt`, and `DecryptRange` are declared at
`internal/crypto/engine.go:79-92`. The direct PUT path extracts `bucket` and
`key` from the authenticated route at `internal/api/handlers.go:1625-1631`, but
drops them when calling `engine.Encrypt` at
`internal/api/handlers.go:1780-1782`. GET similarly knows the route identity at
`internal/api/handlers.go:863-868`, then calls the engine without it at
`internal/api/handlers.go:1338-1343`. Consequently, payload AEAD authenticates
selected metadata but not the backend location: buffered writes build AAD from
algorithm, salt, IV, content type, key version, and size at
`internal/crypto/engine.go:653-660`; chunk encryption and decryption pass
`nil` AAD to `Seal` and `Open` at `internal/crypto/chunked.go:342-350` and
`internal/crypto/chunked.go:637-642`.

The current chunk manifest reports version 1 and the chunk pipeline has no
object-identity input (`internal/crypto/chunked.go:35-43,82-113`). SEC-37 is the
owner of the successor chunked format v2 and its authenticated terminal
trailer. This issue must add bucket/key commitment to that exact v2 data-record
and trailer AAD, not bump it to another competing format. Range translation
currently maps plaintext chunks to ciphertext offsets at
`internal/crypto/range_optimization.go:66-112`; the identity commitment must
therefore be reproducible for independently fetched v2 records without reading
earlier ciphertext.

Encrypted MPU uses a separate chunk pipeline whose IV schedule includes
upload, part, and chunk coordinates, but whose payload `Seal`/`Open` calls also
use nil AAD (`internal/crypto/mpu_encrypter.go:44-64,173-177` and
`internal/crypto/mpu_encrypter.go:320-347`). Its version-1 manifest contains
cryptographic and part layout data but no parent/companion identity or binding
identifier (`internal/crypto/mpu_manifest.go:12-68`). Complete writes the
encrypted manifest to `<key>.mpu-manifest` at
`internal/api/handlers.go:4641-4707`; full and ranged reads locate and decrypt
that companion at `internal/api/handlers.go:4397-4451,4739-4763`. A backend
rename or copy of ciphertext and metadata can therefore preserve valid tags at
the wrong bucket/key, and a separately moved companion is not cryptographically
tied to its parent.

Gateway CopyObject already mediates encrypted copies by reading the source,
decrypting it, and selecting a destination engine at
`internal/api/handlers.go:5098-5220`; this is the correct semantic boundary for
rebinding. The supported migration model likewise reads plaintext through the
gateway and writes it back through the gateway
(`docs/MIGRATION.md:1-36`; the deprecated shim states this at
`cmd/migrate/main.go:0-19`). V1.0-SEC-42 makes those rewrites mandatory for
relocation: backend-native moves of new-format objects must fail AEAD tag or
identity verification, while legacy objects remain readable and become bound
only when rewritten. This follows AEAD's requirement that associated data be
identical at seal and open time [1][2] and uses unambiguous binary encoding as
recommended for cryptographic protocol inputs [3].

## 2. Design Goals & Non-Goals

### Goals

1. **Trusted identity boundary** — every payload encryption/decryption entry
   point receives a validated `ObjectContext{Bucket, Key}` derived from the
   authenticated route or explicitly parsed copy source, never from object
   metadata.
2. **Canonical commitment** — encode bucket and key as ordered, unsigned
   32-bit length-prefixed byte strings in one shared binary AAD grammar, so
   delimiter, prefix, Unicode, and embedded-NUL ambiguities are impossible.
3. **Format separation** — use distinct domains for buffered payloads,
   SEC-37 chunked-v2 data records and trailer, MPU chunks, and MPU manifest
   payloads; include each format's positional fields in canonical fixed-width
   form.
4. **Universal payload enforcement** — all new buffered, chunked-v2, MPU-part,
   and companion-manifest ciphertext is bound by payload AEAD regardless of
   password-derived or `KeyManager` key wrapping.
5. **Fail-closed version dispatch** — explicit new-format markers select only
   their declared decoder; an AEAD failure never triggers legacy/no-AAD/v1
   fallback.
6. **Legacy dual-read** — formats written before V1.0-SEC-42 remain readable
   through their existing explicit legacy branches; all writes emit only the
   bound format.
7. **Relocation semantics** — raw backend moves of bound objects fail, while
   gateway CopyObject and migration perform decrypt-source/re-encrypt-
   destination and produce a fresh binding.
8. **MPU relationship integrity** — a v2 MPU manifest records the parent and
   companion identities plus a shared random binding ID, and both manifest and
   data tags enforce that relationship.

### Non-Goals

1. **No competing chunk format** — framing, trailer layout, and chunked format
   v2 remain owned by V1.0-SEC-37; this issue only extends its AAD inputs.
2. **No backend rename compatibility** — preserving readability after a raw
   backend move would defeat the location-binding objective; use gateway copy
   or migration instead.
3. **No legacy in-place metadata upgrade** — adding a marker cannot bind old
   ciphertext; migration must decrypt and rewrite the payload.
4. **No `KeyManager` interface break** — provider metadata maps remain advisory
   hints because several adapters intentionally ignore them
   (`internal/crypto/keymanager_memory.go:102-136`,
   `internal/crypto/keymanager_cosmian.go:137-178`); payload AEAD is the
   interoperable enforcement layer.
5. **No path normalization** — bucket and key are committed exactly as the S3
   routing/copy parser resolves them; Unicode normalization, slash cleaning,
   URL escaping, case folding, and trimming would change S3 object identity.

## 3. Target Interface / Semantics / Behaviour

### Trusted object context and engine API

```go
// ObjectContext is trusted request identity supplied separately from backend
// metadata. Bucket and Key are exact S3 identity strings after route parsing;
// neither field is read from x-amz-meta-* values.
type ObjectContext struct {
    Bucket string
    Key    string
}

func (o ObjectContext) Validate() error

type EncryptionEngine interface {
    Encrypt(ctx context.Context, object ObjectContext, reader io.Reader, metadata map[string]string) (io.Reader, map[string]string, error)
    Decrypt(ctx context.Context, object ObjectContext, reader io.Reader, metadata map[string]string) (io.Reader, map[string]string, error)
    DecryptRange(ctx context.Context, object ObjectContext, reader io.Reader, metadata map[string]string, plaintextStart, plaintextEnd int64) (io.Reader, map[string]string, error)
    IsEncrypted(metadata map[string]string) bool
    PreferredAlgorithm() string
}

func (e *engine) DecryptRangeOptimized(ctx context.Context, object ObjectContext, reader io.Reader, metadata map[string]string, plaintextStart, plaintextEnd int64) (io.Reader, map[string]string, error)
```

Invariants: `ObjectContext` is immutable by convention, validated before any
key operation or payload read, and contains non-empty bucket and key values
within S3 limits. Nil metadata is valid and untrusted. Context cancellation,
reader ownership, DEK zeroization, and streaming behavior remain unchanged.
This explicit parameter prevents a caller from accidentally treating mutable
backend metadata as authoritative identity and follows the small, typed API
boundary principle [4].

Exact production call sites:

| Call site | Context supplied |
|---|---|
| `handlePutObject`, `internal/api/handlers.go:1781` | `crypto.ObjectContext{Bucket: bucket, Key: key}` |
| normal/optimized GET, `internal/api/handlers.go:1338-1343` | requested `bucket`, `key` |
| CopyObject source decrypt, `internal/api/handlers.go:5198-5220` | parsed `srcBucket`, `srcKey` |
| CopyObject destination encrypt later in `handleCopyObject` | routed `dstBucket`, `dstKey` |
| MPU manifest encrypt, `internal/api/handlers.go:4695` | companion `bucket`, `key + ".mpu-manifest"` |
| MPU manifest decrypt for range/full/size, `internal/api/handlers.go:4444,4758,4818` | fetched companion bucket/key, never parent metadata |
| UploadPartCopy source decrypt/range, `internal/api/upload_part_copy.go:547,605,801,837` | parsed source bucket/key |
| UploadPartCopy manifest decrypt, `internal/api/upload_part_copy.go:946` | source companion bucket/key |

All direct engine uses in tests and benchmarks must be updated with explicit
contexts; no constructor default, variadic argument, empty-context fallback, or
metadata-derived compatibility shim is permitted.

### Canonical AAD grammar

```go
type aadDomain string

const (
    aadBufferedV2       aadDomain = "s3eg/buffered/v2"
    aadChunkedV2Data    aadDomain = "s3eg/chunked/v2/data"
    aadChunkedV2Trailer aadDomain = "s3eg/chunked/v2/trailer"
    aadMPUV2Chunk       aadDomain = "s3eg/mpu/v2/chunk"
    aadMPUV2Manifest    aadDomain = "s3eg/mpu/v2/manifest"
)

func buildObjectAAD(domain aadDomain, object ObjectContext, bindingID []byte, fields ...uint64) ([]byte, error)
```

The exact binary encoding is:

```text
magic       = 8 bytes: 53 33 45 47 41 41 44 00 ("S3EGAAD\x00")
aadVersion  = uint16 big-endian, value 1
domain      = uint32(len(domain)) || UTF-8 bytes(domain)
bucket      = uint32(len(bucketBytes)) || bucketBytes
key         = uint32(len(keyBytes)) || keyBytes
bindingID   = uint32(len(bindingID)) || bindingID
fieldCount  = uint16 big-endian
fields      = fieldCount repetitions of uint64 big-endian
```

Lengths count raw Go string bytes, not runes. The encoder rejects invalid
`ObjectContext`, unsupported domains, a binding ID length other than 16 for new
formats, more than 65535 fields, or any component exceeding `uint32`. It never
sorts fields, reads metadata, normalizes strings, or uses textual delimiters.
Length-prefixing provides an injective encoding for variable strings [3], and
format domains prevent a valid tag for one record role from being reused as
another [1].

Format-specific AAD is fixed as follows:

| Ciphertext | Domain | `fields` in exact order |
|---|---|---|
| Buffered v2 payload | `s3eg/buffered/v2` | empty |
| SEC-37 chunked-v2 data record | `s3eg/chunked/v2/data` | `chunkIndex` |
| SEC-37 chunked-v2 terminal trailer | `s3eg/chunked/v2/trailer` | `chunkCount`, `totalPlaintextLength` |
| MPU v2 data chunk | `s3eg/mpu/v2/chunk` | `uint64(partNumber)`, `chunkIndex` |
| MPU v2 companion manifest payload | `s3eg/mpu/v2/manifest` | empty |

The SEC-37 v2 framing and trailer plaintext do not change here. SEC-42 supplies
the above AAD to the v2 record seals/opens; the 16-byte `bindingID` remains in
authenticated object metadata and is included in both data-record and terminal
AAD without adding trailer bytes. Range reads reconstruct data AAD from
`ObjectContext`, persisted binding ID, and absolute chunk index, and retain
SEC-37's separate terminal preflight before returning a range response.

### Versions, metadata, and dispatch

New writes persist explicit, compactable metadata markers:

```go
const (
    MetaObjectFormatVersion = "x-amz-meta-encryption-format-version"
    MetaObjectBindingID     = "x-amz-meta-encryption-binding-id"
)
```

| Format | New marker | Binding location | Read behavior |
|---|---|---|---|
| Buffered | `MetaObjectFormatVersion=buffered-v2` | 16-byte base64url `MetaObjectBindingID` | Open once with buffered-v2 AAD; tag failure is terminal. |
| Chunked | SEC-37's `chunked-v2` marker | metadata ID authenticated by every data record and the SEC-37 terminal | Dispatch only to SEC-37 v2; data/trailer tag failure is terminal. |
| MPU | `MetaMPUEncrypted=v2`, manifest `Version=2` | main metadata ID, manifest field, and data AAD | Dispatch only to MPU v2; no v1 retry after any v2 failure. |
| Legacy | absent or explicitly older marker | N/A | Existing buffered, chunked-v1/fallback-v1/v2, no-AAD-gated, and MPU-v1 readers remain available. |

Marker parsing is strict: unknown/noncanonical values return an unsupported
format error; malformed/missing binding IDs on a declared bound format return
an invalid-format error before key unwrap. A new-format tag failure returns an
integrity error and MUST NOT call `buildAADLegacy`, no-AAD recovery,
fallback-v1, chunked-v1, or MPU-v1. This prevents downgrade after an
attacker-controlled tag failure and follows fail-closed authenticated-decryption
guidance [1][2].

```go
const mpuManifestVersion = 2

type MultipartManifest struct {

    Algorithm           string          `json:"alg"`

    IVPrefix            string          `json:"iv_prefix"`
    UploadIDHash        string          `json:"uid_hash"`
    WrappedDEK          string          `json:"wrapped_dek"`
    KMSKeyID            string          `json:"kms_key_id,omitempty"`
    KMSProvider         string          `json:"kms_provider,omitempty"`
    KMSKeyVersion       int             `json:"kms_key_ver,omitempty"`
    Parts               []MPUPartRecord `json:"parts"`
    OriginalETag        string          `json:"orig_etag,omitempty"`
    TotalPlainSize      int64           `json:"total_plain"`
}

func (m *MultipartManifest) ValidateFor(parent, companion ObjectContext, bindingID [16]byte) error
```

CreateMultipartUpload generates one random 16-byte binding ID and stores it in
trusted upload state alongside the already-recorded `Bucket` and `Key`
(`internal/mpu/state.go:133-172`). Every MPU chunk uses parent context plus this
ID. Complete emits manifest v2 with exact parent identity, exact companion
identity (`parent.Key + ".mpu-manifest"`), and the same ID. The companion JSON
is encrypted using the companion `ObjectContext` and manifest-v2 AAD; after
decrypting it, `ValidateFor` must match the requested parent, fetched companion,
and main-object metadata binding ID before unwrapping the payload DEK. This
creates both an AEAD-protected companion location and an authenticated
parent-companion relationship.

`NewMPUPartEncryptReader`, `NewMPUDecryptReader`, and range decrypt receive the
new trusted inputs exactly:

```go

```

### KeyManager and relocation semantics

`KeyManager.WrapKey` and `UnwrapKey` signatures do not change. Callers may
continue to pass bucket/key metadata for provider policy or diagnostics, but
the interface documentation must say that metadata is advisory, adapters may
ignore it, and callers MUST NOT rely on it for object-location integrity.
Payload AEAD with `ObjectContext` is the universal enforcement mechanism.

A backend-side copy/rename of bound ciphertext and metadata to any different
bucket or key fails authentication. Gateway CopyObject always decrypts using
the source context and encrypts with the destination context and a fresh
binding ID; same-key copy also rewrites with a fresh ID. The migration procedure
is GET-through-gateway followed by PUT-through-gateway, so every migrated
legacy object receives the current bound format. Companion objects are
gateway-owned implementation details and are never copied independently.

### Tier 2 conformance

Conformance tests use exact key substitution because the current provider
contract provisions one bucket; two keys or prefixes MUST NOT be described as
cross-bucket coverage. True bucket canonicalization remains Tier 1 until the
provider contract safely exposes a second bucket. Chunked cases explicitly use
`harness.WithChunking(true)` and SEC-37's v2 format.

Tests must assert errors before response headers where practical, assert that

destination contexts rather than modifying metadata to simulate identity.

## 7. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| A route/copy path omits or swaps source/destination context, causing unreadable writes or ineffective copy tests. | Make the engine signature mandatory with no default; enumerate every production call site in §3; require source/destination API tests. |
| SEC-42 accidentally forks SEC-37's chunked-v2 framing or changes range offsets. | Block Phase B on SEC-37; modify its v2 implementation in place; golden-test framing and range offsets before/after AAD extension. |
| New-format authentication failure falls through to a permissive legacy branch. | Parse explicit version first and return directly from its decoder; tests instrument each legacy branch and prove it is not entered after a v2 failure. |
| Canonicalization aliases distinct S3 keys. | Commit raw string bytes with fixed order and uint32 lengths; forbid normalization; cover delimiter, NUL, slash, percent, and Unicode cases plus fuzzing. |
| MPU data and companion are individually valid but paired with different parents. | Store one random binding ID in upload state, main metadata, data AAD, and manifest; validate both identities and ID before DEK unwrap. |
| Optimized range GET could omit SEC-37's terminal verification while fetching selected chunks. | Retain SEC-37's fixed-size terminal preflight and additionally bind every fetched chunk with identity/index AAD. |
| Provider adapters ignore `KeyManager` metadata, creating a false integrity assumption. | Keep provider metadata advisory; enforce identity in every payload AEAD path; correct interface and KMS documentation. |
| Raw backend moves become unreadable and surprise operators. | Treat failure as intended behavior; document gateway CopyObject and GET-to-PUT migration prominently in README, migration guide, ADR, and changelog. |
| Legacy support can become an attacker-controlled downgrade. | Select legacy readers only from absent/older format markers; never retry legacy after a declared bound-format parse/tag failure. |
| In-flight MPU state created before deployment lacks a binding ID. | Continue it only through the explicit MPU-v1 completion path; never synthesize a v2 ID after parts were written; new Create calls always produce v2 state. |

## 8. Definition of Done

- [ ] Per `docs/issues/v1.0-issues.md`, every new
  encrypted payload is bound to trusted bucket/key identity.
- [ ] V1.0-SEC-37 is complete first, and SEC-42 extends its chunked format v2
  data/trailer AAD without adding a competing format or changing v2 framing.
- [ ] `ObjectContext` and all engine/MPU signatures exactly match §3; no
  production call site derives it from backend metadata or supplies an empty
  default.
- [ ] Canonical AAD exactly matches the byte grammar, domains, and ordered
  fields in §3 and passes all ambiguity/key-edge tests.
- [ ] Buffered-v2, chunked-v2 data/trailer, MPU-v2 chunks, and MPU-v2 companion
  manifests enforce identity through payload AEAD for password and every
  `KeyManager` provider.
- [ ] Declared new-format parse or tag failure is terminal; all no-fallback
  tests pass.
- [ ] Legacy buffered, chunked/fallback, and MPU formats remain dual-readable
  only through explicit legacy dispatch.
- [ ] MPU v2 records parent identity, companion identity, and one shared random
  binding ID; swapped/moved companions fail before payload DEK use.
- [ ] Raw backend moves fail for bound objects, while gateway CopyObject
  decrypts source/re-encrypts destination and uses a fresh binding ID.
- [ ] GET-through-gateway to PUT-through-gateway migration rewrites legacy and
  moved objects into the current destination-bound format.
- [ ] `KeyManager` metadata is documented as advisory in code and
  `docs/KMS_COMPATIBILITY.md`; no adapter behavior is claimed as universal
  enforcement.
- [ ] All exact tests in §6 pass, including ranges, MPU, copy, migration,
  integration, race, and FIPS checks; changed critical-package coverage is at
  least 85%.
- [ ] ADR 0017, README, migration guide, KMS compatibility guide, and changelog
  describe the implemented behavior and backend-move incompatibility.
- [ ] `go vet ./...`, `go vet -tags=fips ./...`, and `golangci-lint run` are
      clean for changed code.
- [ ] All SEC-42 Tier 2 functions are registered with exact capability gates;
      composite gates require all bits and chunked cases explicitly enable
      chunking.
- [ ] `make test-conformance-local` and `make test-isolation-check` pass; tests
      make no false cross-bucket claim and use portable S3 relocation only.
