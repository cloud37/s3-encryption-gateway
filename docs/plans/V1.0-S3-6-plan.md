# V1.0-S3-6 — Centralize Encrypted Object Metadata Handling (and Eliminate Drifting Code Branches) — Implementation Plan

Status: Draft
Owner: S3 Compatibility / Crypto / API
Priority: P1
Labels: `milestone:v1.0`, `area:compat`, `area:crypto`, `area:api`

> Scope clarified relative to the tracker entry at
> `docs/issues/v1.0-issues.md:44`. The tracker entry asks for one canonical
> write-side persistence path and one canonical read-side response decorator
> for encrypted-object metadata. At the maintainer's request this plan widens the
> scope. It covers **every place in the gateway where one decision is
> re-implemented independently per code path**: metadata key sets, object-format
> classification, plaintext-size derivation, MPU manifest loading, S3 error and
> decrypt-failure mapping, S3 operation classification, and backend key
> normalization. The plan replaces each with one owner and adds guard tests so
> the branches cannot drift apart again. The history of fixes that were applied
> to one path and missed in another (§1.1) motivates the wider scope.
> Work that was surfaced but is too large or orthogonal is listed in §10.

It still carries a fail-open branch that forwards **ciphertext** when decryption fails (`handlers.go:730-731`). It was nevertheless maintained during the ETag fix (CHANGELOG entry of `a129d48`), which illustrates the cost of dead branches.

Defects found between the read writers:

1. **Two different "is internal metadata" predicates.**
   `api.isEncryptionMetadata` (`handlers.go:2670-2697`) lists 13 keys.
   `crypto.IsEncryptionMetadata` (`internal/crypto/engine.go:2704-2731`) lists 27.
   The API list omits `MetaEncrypted`, `MetaKeyVersion`,
   `MetaWrappedKeyCiphertext`, `MetaKMSKeyID`, `MetaKMSProvider`,
   `MetaKDFParams`, `MetaFallback*`, `MetaObjectFormatVersion`,
   `MetaObjectBindingID`, `MetaMPUManifestVersion`, `MetaEncryptedMetadata`,
   `MetaMPUEncrypted` and every compact alias. HEAD (R1) therefore exposes these
   gateway-internal headers to clients, including the wrapped DEK and KMS key ID.
2. **Response cache stores empty bodies.** On a full GET, `decryptedData` is only
   assigned in the buffered-range branch (`handlers.go:1585-1608`). The cache
   write at `:1665-1672` runs only when `rangeHeader == nil`, so it always stores
   `Data == nil`. The next cache hit (`:1036-1041`) returns `200` with the
   plaintext `Content-Length` and an **empty body**. The only cache tests are in
   `internal/cache/cache_test.go`, and no handler test exercises a hit.
3. **Cache staleness.** The cache hit HEADs the backend (`:1022`) for the
   completeness preflight but never compares the backend ETag. A write through
   another gateway replica is served stale until the TTL expires.
4. **`response-*` override query parameters are accepted but never applied.**
   The allowlist is in `internal/api/auth.go:46-48` and
   `internal/api/authorization.go:293-295`, but no handler reads them (grep for
   `response-content-type` finds only those allowlists). Presigned GETs with
   `response-content-disposition` get the stored header back.
5. `Content-Encoding`, `Content-Language` and `Expires` are never persisted for
   encrypted objects. `HeadObject` in the backend client also does not extract
   `Content-Encoding` (`internal/s3/client.go:716-727`), while `GetObject` does
   (`:648-650`).

### 1.4 Object-format classification — 16 inline copies

The MPU marker `crypto.MetaMPUEncrypted` is compared inline in 16 places. The
comparisons disagree:

- `handlers.go:1106,1377,2609,3023,5644`, `upload_part_copy.go:523`: `== "true" || == "v2"`.
- `handlers.go:1283` (passthrough-range guard): `!= "true"` only. A v2 MPU
  object would slip through if its other markers were absent.
- **`handlers.go:2366` (`cleanupMPUManifest`): `!= "true"` → return.** Every
  current encrypted MPU object is written with `"v2"` (`handlers.go:3481`), so
  **DeleteObject and DeleteObjects (`:2475`, `:6085`) never delete v2
  manifests**. The conformance test `testDeleteVersionedEncryptedMPU` seeds the
  legacy value `"true"` (`test/conformance/put_get_test.go:231`), so the defect
  is invisible to the suite.
- `handlers.go:5569` (CopyObject preflight): `!= "true"`.
- **ListObjects completed-MPU size translation** calls
  `readMPUManifestTotalPlainSize(…, nil /* mainMeta */, …)`
  (`handlers.go:2891-2892`). With `mainMeta == nil`, `isV2` is false
  (`:5226`) and the v2 manifest goes to `engine.Decrypt`, which rejects the
  `mpu-manifest-v2` marker (`engine.go:949-951`). Listings silently keep
  ciphertext sizes for every v2 MPU object.

Chunked, legacy and plaintext classification is also scattered:
`crypto.IsChunkedFormat` on expanded metadata in some places and on raw
metadata in others (`handlers.go:2592` uses raw `MetaChunkedFormat`). Other
checks are `engine.IsEncrypted` (`:1127,1488`), `crypto.IsEncryptedMetadata`
(`:1112`), a raw `MetaEncrypted` presence check (`:1283`), and
`classifyCopySource`'s `SourceClass` (`upload_part_copy.go:510-573`), which is
the only structured classifier and is used only by UploadPartCopy.

The MPU manifest key is derived in 9 places, either from `MetaFallbackPointer`
with a fallback to `key + ".mpu-manifest"` (`handlers.go:2614-2617,4732-4735,5113-5116`,
`upload_part_copy.go:1076-1079`) or as a hard-coded suffix
(`handlers.go:2370,2891,3024,3484,5035,5071,5079`). The constant
`mpuManifestSuffix` (`handlers.go:2972`) is used in only two of them.

### 1.5 MPU manifest loading — four copies

"Fetch companion → check v2 marker → decode binding → decrypt → unmarshal →
`ValidateFor`" is implemented four times: `serveMPURangedGet`
(`handlers.go:4731-4820`), `decryptMPUObject` (`:5112-5167`),

### 1.7 Metadata key registry — five hand-maintained lists

The same key set is enumerated by hand in five places:

- `crypto.IsEncryptionMetadata` (`engine.go:2704-2731`)
- `api.isEncryptionMetadata` (`handlers.go:2670-2697`)
- `compactEncryptionMetadata` / `expandEncryptionMetadata` (`metadata_compaction.go:92-250`)
- `isCompactedKey` (`metadata_compaction.go:253-273`)
- the detection list in `ExpandMetadataForAPI` (`metadata_compaction.go:18`)

The last one detects only 10 of the 23 aliases. `isCompactedKey` omits
`x-amz-meta-ct`, `x-amz-meta-ccache` and `x-amz-meta-cdisp`. Those aliases
therefore survive expansion as *user* metadata, and `restoreCompactedEncryptedObjectHeaders`
(`handlers.go:2349-2359`) exists only to patch that leak. The short aliases
(`x-amz-meta-a`, `-s`, `-i`, `-e`, `-c`, `-m`, …) are also legal client
user-metadata names. A client that sends `x-amz-meta-a: foo` on an encrypted
bucket has the value interpreted as the algorithm alias by
`ExpandMetadataForAPI`, and the value is dropped from its HEAD view.
Client-supplied reserved long-form keys (e.g. `x-amz-meta-encrypted-mpu`,
`x-amz-meta-encryption-fallback-ptr`) are not rejected on PUT. The engine
copies all caller metadata before stamping its own keys (`engine.go:667-671`,
`:1224-1229`), and the markers it does not overwrite are persisted.

### 1.8 Cross-cutting handler duplication

- **79** `S3Error` literals in `handlers.go`, 12 in `upload_part_copy.go`, 10
  in `object_lock.go`, and **119** `RecordHTTPRequest` calls in `handlers.go`,
  each re-pairing "write XML + record metric" by hand. HEAD must not carry a
  body; only `writeChunkedCompletenessError` (`handlers.go:5959-5963`) handles
  that.
- Decrypt-failure → S3 error mapping is duplicated. `EncryptionConfigurationMismatch`
  appears three times (`handlers.go:1499-1508,1547-1555,719-728`), and the KDF
  mapping appears twice (`:1534-1540,710-717`).
- Two backend HTTP forwarders build their own transports: `forwardToBackend`
  (`internal/api/utils.go:149`) and the dead `forwardSignatureV4Request` (`handlers.go:629-649`).
- Three independent S3 operation classifiers:
  - the gorilla/mux route table (`handlers.go:292-448`)
  - `classifyAuthorizationOperation` / `classifyObjectAuthorizationOperation` (`internal/api/authorization.go:206,269`)
  - `s3OperationName` (`internal/api/s3_instrumentation.go:174-288`)

  Drift between these three produced `552f1d9`, `c292972` and several V1.0-AUTH-2
  verification failures (tracker history in `docs/issues/v0.12-issues.md`).
- Backend key normalization is inconsistent:
  - `extractMetadata` lower-cases user keys (`internal/s3/client.go:841-864`).
  - Standard headers are inserted in canonical case (`:627-650,716-727`).
  - The GCS wrapper then lower-cases *everything* (`gcs_client.go:64,72`).

  On GCS, every handler lookup of `metadata["Content-Length"]` or `["ETag"]`
  therefore misses.

### 1.9 Objective

The existing state is insufficient because correctness depends on a developer
remembering 5–16 sibling copies of each rule. The objective is structural:

1. Each rule gets exactly one owner (a registry, a classifier, a resolver, a
   projector or a mapper).
2. Every path calls that owner.
3. Guard tests fail when a new inline copy is introduced.

Wire formats, AEAD/AAD construction and S3 response semantics stay unchanged
except where the current behavior is a documented defect (§3.6). Relevant
prior decisions: ADR 0002 (MPU interop), ADR 0006 (UploadPartCopy), ADR 0009
(encrypted MPU), ADR 0013 (self-contained envelope), ADR 0016
(authenticated chunked completeness) and ADR 0017 (object-location binding) [1][2].

## 2. Design Goals & Non-Goals

### Goals

1. **Single metadata key registry.** Every gateway-owned metadata key has
   exactly one declaration: canonical name, compact alias, legacy aliases and
   class. That declaration is in `internal/crypto/metakeys.go`.
   `IsEncryptionMetadata`, the reserved-key predicate, compaction, expansion,
   alias detection and the protected standard-header set are all *derived* from
   it. No other file in `internal/` contains an `"x-amz-meta-enc…"` or
   `"x-amz-meta-encrypt…"` string literal (enforced by a guard test).
2. **Single object classifier.** `crypto.ClassifyObject` is the only code that
   decides plaintext / buffered / fallback / chunked-v1 / chunked-v2 / MPU-v1 /
   MPU-v2. Unknown marker values fail closed with `ErrUnsupportedObjectFormat`.
   No inline `MetaMPUEncrypted]` comparison remains in `internal/api`.
3. **Single write-side persistence path.** PutObject, CopyObject (COPY and
   REPLACE), CreateMultipartUpload and the streaming-size backfill build
   client-visible metadata via `parseWriteMetadata` / `resolveCopyWriteMetadata`.
   They persist via `buildPersistPlan`. The engine stamps protected standard
   headers through one helper on every encrypt branch.
4. **Single read-side response projector.** HEAD, full GET, all ranged GET
   variants, MPU GET, MPU ranged GET and cache hits set object headers only via
   `projectObjectHeaders` (pure) plus `writeObjectHeaders`. No other code in
   `internal/api` sets `Content-Length`, `Content-Range`, `ETag` or
   `x-amz-version-id` on an object response (enforced by a guard test).
5. **Single plaintext-size resolver and single MPU manifest loader.** Both are
   used by HEAD, GET, ListObjects, CopyObject, UploadPartCopy and size-cache
   population.
6. **Documented, tested precedence.** The field-ownership and precedence
   tables in §3.4/§3.5 are published in `docs/METADATA_MODEL.md` and ADR 0018,
   and a table-driven unit test covers every row.
7. **Backward compatibility.** Objects written by 0.10–0.12 (buffered legacy,
   buffered-v2, fallback v1/v2/v3, chunked v1/v2, MPU v1/v2, compacted,
   metadata-blob, self-contained envelope) remain readable. Golden tests pin
   the response headers produced for fixtures of each format.
8. **Drift guards.** AST-based guard tests and a route-classification parity
   test turn each "forgot the sibling path" failure mode into a CI failure.

### Non-Goals

1. **Conditional requests (`If-Match`, `If-None-Match`, `If-Modified-Since`, 304/412).**
   They are not implemented anywhere today. The projector reserves a hook, but
   the feature is tracked as a follow-up (§10), because it adds new S3
   semantics rather than removing drift.
2. **`x-amz-tagging-directive` and copying source tags.** This is orthogonal to
   metadata. It is a follow-up.
3. **Rewriting the gorilla/mux route table into a single dispatcher.** This plan
   adds a parity test across the three classifiers instead. Merging them is a
   larger authorization-sensitive refactor (§10).
4. **Config env/YAML/Helm single-source binding.** The drift class is real
   (issue #207), but it is a separate subsystem (`internal/config/config.go:1196-2040`,
   ~850 lines of imperative env mapping). It is a follow-up with its own plan.
5. **Changing any AEAD/AAD construction, manifest wire format or KDF.** New
   protected standard headers (Content-Encoding, Content-Language, Expires)
   are stored as ordinary protected metadata keys. The same is already true of
   Content-Type in v2 formats, where it is not part of the AAD
   (`engine.go:768`, `buildObjectAAD`).
6. **ListObjects ETag translation.** ListObjects keeps returning backend ETags,
   as documented at `handlers.go:2849-2850`. The divergence from HEAD is recorded in
   the precedence doc.

## 3. Target Interface / Semantics / Behaviour

### 3.1 Standard-header model (`internal/objectmeta`, new leaf package)

The package uses only the standard library, so `crypto`, `api` and `s3` can
all import it without cycles.

```go
// Package objectmeta owns the client-visible S3 "system-defined" object headers
// that the gateway persists and restores.
//
// Invariants:
//   - Standard is a value type; zero value means "header absent".
//   - Header names are compared case-insensitively on input and emitted in
//     canonical MIME form (http.CanonicalHeaderKey) on output.
//   - No function in this package performs I/O or holds secrets.
package objectmeta

type Standard struct {
	ContentType, CacheControl, ContentDisposition string
	ContentEncoding, ContentLanguage, Expires     string
}

// Names lists the canonical header names in a fixed order. It is the only list
// of standard headers in the repository.
var Names = [...]string{"Content-Type", "Cache-Control", "Content-Disposition",
	"Content-Encoding", "Content-Language", "Expires"}

func FromHeader(h http.Header) Standard                        // request → model
func Split(meta map[string]string) (Standard, map[string]string) // case-insensitive; returns remainder
func (s Standard) Get(name string) string
func (s Standard) Set(name, value string) Standard
func (s Standard) ApplyTo(meta map[string]string)                 // writes canonical keys for non-empty fields
func (s Standard) Overlay(o Standard) Standard                    // non-empty fields of o win

// NormalizeBackendKeys returns a copy where x-amz-* keys are lower-case and
// every other key is http.CanonicalHeaderKey. Every s3.Client adapter applies it
// at its return boundary.
func NormalizeBackendKeys(meta map[string]string) map[string]string
```

*Rationale:* a typed struct makes "forgot Cache-Control in path Y" a compile-time
omission instead of a missing map key. The fixed `Names` array is the single
enumeration that `isStandardMetadata`, `cloneMetadataWithoutStandardHeaders`,
the Copy header loop and the CreateMPU loop currently duplicate. This follows
Go's small-package guidance of defining shared types at the lowest layer that
needs them [3].

### 3.2 Metadata key registry (`internal/crypto/metakeys.go`, new)

```go
type MetaKeyClass uint8

const (
	// MetaClassControl: crypto/format control. Never client-visible, never
	// client-writable. Participates in compaction iff Compact != "".
	MetaClassControl MetaKeyClass = iota + 1
	// MetaClassProtectedStandard: gateway-stored plaintext value of a standard
	// header (Header names the objectmeta.Names entry).
	MetaClassProtectedStandard
	// MetaClassStructural: gateway markers that must survive compaction
	// untouched (MPU markers, encrypted-metadata blob). Never client-visible.
	MetaClassStructural
)

type MetaKeySpec struct {
	Canonical string   // e.g. MetaContentType
	Compact   string   // "" when the key is never compacted
	Legacy    []string // historical spellings accepted on read only, e.g. "encryption-content-type"
	Class     MetaKeyClass
	Header    string   // objectmeta.Names entry for MetaClassProtectedStandard
	// LegacyEncryptionPredicate is true for keys that the pre-registry
	// crypto.IsEncryptionMetadata returned true for. Frozen for back-compat.
	LegacyEncryptionPredicate bool
}

// Invariants:
//   - Canonical, Compact and every Legacy value are globally unique (init() panics otherwise).
//   - Lookup is case-insensitive.
//   - The registry is immutable after package init; safe for concurrent use.
func MetaKeys() []MetaKeySpec
func LookupMetaKey(key string) (MetaKeySpec, bool)
func IsEncryptionMetadata(key string) bool      // == spec.LegacyEncryptionPredicate (output set unchanged)
func IsGatewayReservedKey(key string) bool      // any form of any registry key, plus "x-amz-meta-original-content-length"
func ProtectedStandardKeys() []MetaKeySpec      // Class == MetaClassProtectedStandard, in objectmeta.Names order
func CompactAliases() map[string]string         // canonical → compact
func HasCompactAlias(meta map[string]string) bool // replaces the 10-entry list in ExpandMetadataForAPI
```

New protected keys (all `MetaClassProtectedStandard`):

| Header | Canonical | Compact | Legacy |
|---|---|---|---|
| Content-Type | `x-amz-meta-encryption-content-type` (existing) | `x-amz-meta-ct` | `encryption-content-type` |
| Cache-Control | `x-amz-meta-encryption-cache-control` (existing) | `x-amz-meta-ccache` | `encryption-cache-control` |
| Content-Disposition | `x-amz-meta-encryption-content-disposition` (existing) | `x-amz-meta-cdisp` | `encryption-content-disposition` |
| Content-Encoding | `x-amz-meta-encryption-content-encoding` (**new**) | `x-amz-meta-cenc` | — |
| Content-Language | `x-amz-meta-encryption-content-language` (**new**) | `x-amz-meta-clang` | — |
| Expires | `x-amz-meta-encryption-expires` (**new**) | `x-amz-meta-cexp` | — |

`isCompactedKey`, `compactEncryptionMetadata`, `expandEncryptionMetadata` and
the `ExpandMetadataForAPI` detection list are rewritten as loops over
`MetaKeys()`. The resulting compacted and expanded maps for every existing key
must be byte-identical to today's (golden test A5). The new
`ct`/`ccache`/`cdisp` entries in `isCompactedKey` fix the leak described in §1.7.
They are safe because those aliases are only ever written by the gateway.

*Rationale:* "table-driven data over repeated control flow" [4]. The frozen
`LegacyEncryptionPredicate` column lets the registry replace the hand-written
list without changing which keys `CompactMetadata` copies through
(`metadata_compaction.go:48-52`). The set is proven unchanged by
`TestIsEncryptionMetadata_UnchangedSet`.

**Request parsing (`internal/api/object_write.go`, new):**

**Copy directive table:**

| `x-amz-metadata-directive` | User metadata | Standard headers | Request `x-amz-meta-*` / standard headers |
|---|---|---|---|
| absent or `COPY` | source's (decrypted view) | source's (decrypted view) | **ignored** (AWS semantics [5]) |
| `REPLACE` | request's only | request's only; Content-Type defaults to `application/octet-stream` (same as PUT, `handlers.go:1955-1958`) | authoritative |
| any other value | — | — | `400 InvalidArgument`, "Unknown metadata directive." |

The request's own `Content-Length`/`ETag` never enter destination metadata;
only `objectmeta.Names` headers do. Copying an object onto itself under COPY
stays **permitted**, because the gateway uses same-key re-encryption for
rotation and migration. This deliberately diverges from AWS and is documented.

**Reserved-key rejection:** any `x-amz-meta-*` for which
`crypto.IsGatewayReservedKey` is true yields `400 InvalidArgument` "Metadata key
%q is reserved by the encryption gateway." The rule applies on PUT,
CreateMultipartUpload and CopyObject(REPLACE), for encrypted and bypass buckets
alike. It is fail-closed: today such keys either corrupt classification (§1.7)
or are silently dropped.

**Backend adapters (`internal/s3`):** `PutObject`, `CreateMultipartUpload` and
`CopyObject` call `objectmeta.Split` on the incoming map. They set native
`ContentType`/`CacheControl`/`ContentDisposition`/`ContentEncoding`/`ContentLanguage`/`Expires`
fields from the result and send the remainder as user metadata.
`cloneMetadataWithoutStandardHeaders` is deleted. When `metadata != nil`,
`CopyObject` sets `MetadataDirective: types.MetadataDirectiveReplace`, which
fixes the size backfill. Every adapter's `GetObject`/`HeadObject`/`CopyObject`
return value passes through `objectmeta.NormalizeBackendKeys`. The GCS
`lowercaseKeys` is narrowed to `x-amz-meta-*` keys only.

### 3.5 Read-side semantics (the projector)

```go
// objectResponseSource is everything the projector needs; built once per
// request by loadObjectView.
type objectResponseSource struct {
	Class      crypto.ObjectClass
	Meta       map[string]string // expanded backend metadata, blob decrypted
	Decrypted  map[string]string // engine decMetadata when a body was decrypted (fallback formats carry
	                             // authoritative metadata inside the body); nil for HEAD
	PlainSize  int64             // exact plaintext size, -1 if unknown
	BackendETag string
}

type responseShape struct {
	Method    string            // GET | HEAD
	Range     *byteRange        // nil → full object; {Start, End} inclusive plaintext offsets
	VersionID string            // request versionId (fallback only)
	Overrides url.Values        // response-* query parameters; honoured on GET only
}

// projectObjectHeaders is PURE. It is the only function that decides which
// object headers a client sees.
//
// Invariants:
//   - Never emits a key for which crypto.IsGatewayReservedKey is true.
//   - Emits only headers in the allowlist: objectmeta.Names, x-amz-meta-*,
//     ETag, Last-Modified, Content-Length, Content-Range, Accept-Ranges,
//     x-amz-version-id, x-amz-object-lock-*, x-amz-storage-class,
//     x-amz-mp-parts-count. Unknown backend keys are dropped (fail-closed).
//   - Content-Length/Content-Range are computed from PlainSize and Range, never
//     copied from the backend, for Encrypted objects.
func projectObjectHeaders(src objectResponseSource, shape responseShape) (http.Header, error)

// writeObjectHeaders copies the projection into w.Header(). It is the only
// caller of w.Header().Set for object-body responses.
func writeObjectHeaders(w http.ResponseWriter, h http.Header)
```

**Field ownership and precedence (response):**

| Field | Plaintext / bypass object | Encrypted single-PUT (all buffered/chunked/fallback) | Encrypted MPU (v1/v2) |
|---|---|---|---|
| Content-Type, Cache-Control, Content-Disposition, Content-Encoding, Content-Language, Expires | `response-*` override (GET) > backend native | override > `Decrypted` protected value (fallback) > `Meta` protected value (canonical > compact > legacy alias) > backend native (legacy objects written before `7cbc1d0`) | override > backend native (set at CreateMPU) |
| `x-amz-meta-*` | backend, minus reserved | `Decrypted` (fallback) ∪ `Meta`, minus reserved | backend, minus reserved |
| ETag | backend | `quoteETag(MetaOriginalETag)` if present, else backend | backend (multipart ETag) |
| Content-Length | backend (full) / range size | `PlainSize` (full; omitted when -1) / range size | manifest `TotalPlainSize` / range size |
| Content-Range | `bytes s-e/total` on 206 | `bytes s-e/PlainSize` | `bytes s-e/TotalPlainSize` |
| Accept-Ranges | `bytes` | `bytes` | `bytes` |
| Last-Modified, object-lock, storage class, parts-count | backend | backend | backend |
| x-amz-version-id | backend value > request `versionId` | same | same |

`response-*` overrides map as follows: `response-content-type`→Content-Type,
`response-content-language`, `response-expires`, `response-cache-control`,
`response-content-disposition`, `response-content-encoding`. They are applied
only on GET and only when the request was authenticated (presigned or signed).
Anonymous requests are already rejected by `AuthMiddleware`, so the check is
implicit in reaching the handler [6].

**Plaintext-size resolver (`internal/api/object_size.go`, new):**

```go
type plaintextSize struct {

	Exact bool
	Source string // "chunked-terminal" | "chunked-formula" | "original-size" | "legacy-aead" | "mpu-manifest" | "backend"

// Precedence per format:
//   Chunked v2 : authenticated terminal (preflight) > formula(Content-Length, ChunkSize, v2)
//   Chunked v1 : formula(Content-Length, ChunkSize, v1) > MetaOriginalSize > chunk-count upper bound
//   Buffered*  : MetaOriginalSize > Content-Length - AEAD overhead(algorithm)
//   Fallback   : MetaOriginalSize (never the ct-16 formula; the body contains metadata)
//   MPU        : manifest.TotalPlainSize (fail-closed on manifest error for GET/Copy;
//                HEAD/List keep the documented fail-soft ciphertext size + warning)
//   Plaintext  : Content-Length
```

**Response cache:** an entry stores `{source objectResponseSource (sans Decrypted), body []byte, backendETag}`.

- **Fill:** only after a full GET whose body streamed completely. A bounded
  `io.TeeReader` captures the body when `PlainSize >= 0` and
  `PlainSize <= cfg.Cache.MaxSize`. The captured length must equal `PlainSize`,
  otherwise the entry is discarded.
- **Hit:** requires the (already performed) HEAD's ETag to equal `backendETag`.
  The hit re-projects through `projectObjectHeaders` with the current request's
  `responseShape`, so overrides and version headers are applied uniformly.

## 6. Test Strategy

Every test below is assigned to exactly one tier from `docs/TESTING.md`:

- **Tier 1** tests have no build tag and run in `go test ./...` and `make test`.
  They never need Docker. Backends are faked with the existing
  `mockS3Client` (`internal/api/handlers_test.go:64`) or with an
  `httptest.Server` for SDK-level adapter tests. Cryptographic fixtures come
  from committed `testdata/`.
- **Tier 2** tests carry the `conformance` build tag, live in
  `test/conformance/`, and follow the contract listed in Phase I.
- **No Tier 3 test** is added. Nothing in this plan needs load, soak or chaos
  proof.

Tier 1 rules this plan must respect:

- **Budget.** The whole suite runs in < 60 s. The new Tier 1 tests must add
  ≤ 5 s in total: no real KDF cost (use `WithPBKDF2Iterations` minimum or
  pre-generated fixtures), and no objects > 1 MiB.
- **Deterministic.** No `time.Sleep`, and concurrency is coordinated with
  channels or `sync.WaitGroup`. A flaky Tier 1 test is a P0 bug.
- **Race detector.** Every Tier 1 test runs under `-race` via `make test`.

## 7. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Registry rewrite changes which keys `CompactMetadata` copies, and existing compacted objects become unreadable | `LegacyEncryptionPredicate` column frozen to today's 27 keys. `TestIsEncryptionMetadata_UnchangedSet` and `TestCompactExpand_GoldenUnchanged` must pass **before** A6 lands (promoted to DoD). |
| Adding `ct`/`ccache`/`cdisp` to `isCompactedKey` hides a real client key of that name | Those names become reserved (B10). Objects that already carry them are gateway-written aliases (only the gateway emits them in compacted profiles). Documented in CHANGELOG. |
| Reserved-key rejection (B10) breaks a client that uses short names like `x-amz-meta-a` | Rejection message names the key. CHANGELOG lists every reserved name. Such keys are already mis-read on encrypted buckets (§1.7), so the change turns silent corruption into an explicit error. |
| COPY-directive change (B6) surprises clients that relied on request headers being merged under COPY | This matches AWS [5]. The CHANGELOG entry is flagged. `TestResolveCopyWriteMetadata_DirectiveTable` pins both directives. REPLACE keeps request authority. |
| Projector allowlist drops a backend header a client relied on | The allowlist is derived from S3 GetObject response headers [7]. The golden test records headers before and after for each format, and any removed header must be justified in ADR 0018. |
| Cache fill buffers large bodies | Fill only when `PlainSize ≤ cfg.Cache.MaxSize`. The bounded tee discards on overflow, and there is no fill for unknown sizes. |
| `ClassifyObject` fail-closed on unknown markers makes previously "readable" odd objects return 500 | Such objects were previously misrouted (e.g. treated as plaintext → ciphertext served). A 500 is the fail-closed outcome. The error is logged with the key and marker value, never the body. |
| Manifest-pointer equality check rejects objects whose pointer differs from `key+suffix` | The gateway only ever writes `key + ".mpu-manifest"` (`handlers.go:3484`). The golden MPU fixtures prove readability. A differing pointer is by definition not gateway-written (security-critical → DoD). |
| Deleting `forwardSignatureV4Request` removes coverage of a code path someone re-enables | The function has no callers. Its fail-open ciphertext branch (`handlers.go:730-731`) is a liability. H1 prevents reintroducing a second object response writer. |
| GCS key-normalization change alters metadata seen by existing GCS deployments | Only standard keys change case, back to canonical, which is what every handler lookup already expects. User keys stay lower-case as before. Covered by `TestGCSLowercaseKeys_OnlyUserMetadata`. |
| Large refactor of `handleGetObject` regresses range correctness | The golden ranged-GET headers, the existing ranged conformance suite (`test/conformance/ranged_test.go`) and the matrix open-ended/suffix range cells all run in `make test-conformance`. The phases land as separate commits. |
| First-chunk read-ahead for all formats adds latency | Bounded to one chunk (≤ 1 MiB). It is already done for MPU. The implementer records before/after `benchstat` output for `BenchmarkHeadObject_Chunked` in the PR, and a > 10 % regression blocks merge in review. There is no CI gate (§6). |
| New protected keys change metadata size and trigger fallback earlier on header-limited providers | Keys are only stamped when the client sends the header. Compact aliases are 12–15 bytes. `needsMetadataFallback` (`engine.go:2237`) remains the single decision point. |

## 10. Follow-ups / Out-of-scope items surfaced during planning

1. **Config single-source binding.** `internal/config/config.go:1196-2040` maps
   environment variables imperatively for ~259 YAML fields. Issue #207 shows the
   drift class. The proposal is a declarative `env:"…"` struct tag, one
   reflective loader, and a parity test against `config.yaml.example` and
   `helm/s3-encryption-gateway/values.schema.json`. This needs its own plan
   (suggested ID V1.0-CONFIG-2).
2. **Single S3 dispatcher.** Collapse the mux route table, `s3OperationName`
   and the authorization classifiers into one `ClassifyS3Operation` that feeds
   routing, metrics and authorization. H3's parity test is the safety net this
   refactor would need.
3. **Conditional requests** (`If-Match`/`If-None-Match`/`If-Modified-Since`/`If-Unmodified-Since`)
   on GET/HEAD. `projectObjectHeaders` already owns ETag and Last-Modified, so
   this becomes one hook.
4. **`x-amz-tagging-directive`** and source-tag copy on CopyObject.
5. **Bucket-handler error helper adoption.** Extend `writeObjectError`-style
   helpers to the ~40 bucket and passthrough handlers excluded from Phase G.
6. **ADR numbering collision.** Two ADRs are numbered 0016. Renumber
   `0016-per-credential-authorization.md` and fix references.
7. **ListObjects ETag translation** for encrypted objects, which requires a
   HEAD or size-cache extension for ETags.
8. **`x-amz-website-redirect-location`, `x-amz-storage-class` and SSE header
   persistence** for encrypted PUT and Copy. Adding them to `objectmeta` is a
   one-line change after this plan, but each needs its own compatibility review.
