## 1. Context & Current State

`ValidateSignatureV4` authenticates only the seed request signature. It derives
the SigV4 signing key and compares the calculated seed signature with
`hmac.Equal`, but then discards the signing key and returns only `error`
(`internal/api/auth.go:59-189`). `AuthMiddleware` therefore has no verified,
request-scoped material with which to authenticate the body after the seed
signature succeeds (`internal/api/auth_middleware.go:129-166`). The canonical
request does include the literal `X-Amz-Content-Sha256` value
(`internal/api/auth.go:443-458`), but that authenticates the selected payload
mode, not the subsequent per-chunk signature chain [1][2].

`AwsChunkedReader` currently parses a line with `ReadString('\n')`, applies
`strings.TrimSpace`, accepts arbitrary extensions, discards two unchecked bytes
after each data chunk, and returns EOF immediately on the zero chunk
(`internal/api/aws_chunked_reader.go:27-99`). It neither bounds header lines nor
requires exact CRLF. It does not validate `chunk-signature`, consume or validate
trailers, compare decoded length, require physical EOF, or reject trailing
bytes. Its tests use placeholder signatures and assert decoding only
(`internal/api/aws_chunked_reader_test.go:10-91`).

Both `handlePutObject` and `handleUploadPart` classify a body as AWS-chunked via
the open-ended predicate `strings.HasPrefix(contentSha256, "STREAMING-")`, then
place the permissive decoder directly in the encryption/backend pipeline
(`internal/api/handlers.go:1763-1777`, `internal/api/handlers.go:3794-3808`). A
new or misspelled mode is consequently accepted as though it were supported.
Current regression tests explicitly pass non-cryptographic values such as
`first` and `final` while expecting successful object/part storage
(`internal/api/chunked_upload_regress_test.go:34-61`,
`internal/api/encrypted_mpu_handler_test.go:1339-1408`).

Backend writes begin only after an encryption reader has been constructed, but
the backend consumes that reader and can therefore observe a framing or
signature error late in the operation (`internal/api/handlers.go:1978`,
`internal/api/handlers.go:3963`). Encrypted MPU state is appended after the
backend `UploadPart` succeeds (`internal/api/handlers.go:3976-3990` and the
following append block), while `StateStore.AppendPart` is the persistent MPU
mutation (`internal/mpu/state.go:88-104`). The target is stricter: completely
authenticate and frame-check each streaming request body before invoking any
object/part backend mutation or MPU-state mutation, while retaining bounded
memory through a removable spool.

## 2. Design Goals & Non-Goals

### Goals

1. **Closed payload-mode classification** — classify every supported
   `X-Amz-Content-Sha256` streaming token by exact equality and reject every
   unknown `STREAMING-*` value before reading or forwarding the body.
2. **Seed-gated context** — `ValidateSignatureV4` returns a request-scoped
   signing context only after the seed signature has passed constant-time
   comparison; no context is available on any validation failure.
3. **Complete signed-chain verification** — verify every signed data chunk and
   the final zero chunk in sequence, using the previous accepted signature and
   constant-time comparisons [1].
4. **Trailer verification** — authenticate signed-trailer variants, require the
   trailer declaration and received trailer set to match, and verify supported
   checksum trailers over the decoded payload [2][3].
5. **Strict unsigned framing** — unsigned streaming variants receive the same
   exact CRLF, bounded line/trailer, decoded-length, final-zero, EOF, and
   trailing-byte validation as signed variants.
6. **Atomic rejection** — a body that fails mode, signature, framing, trailer,
   checksum, decoded-length, EOF, or limit validation causes no backend
   `PutObject`, no backend `UploadPart`, and no MPU-state create/append/update.
7. **Secret hygiene** — zeroize all derived signing-key bytes and prior
   signature bytes when verification ends, errors, closes, or panics through a
   deferred cleanup owner.
8. **Interoperability evidence** — cover official AWS request examples and
   independently generated AWS SDK-style vectors, including signed payload and
   signed-trailer modes.

### Non-Goals

1. **SigV2 body authentication** — SigV2 has no SigV4 streaming signature
   chain; existing policy remains unchanged.
2. **Event-stream signing** — `STREAMING-AWS4-HMAC-SHA256-EVENTS` is not an S3
   upload payload mode and is rejected by the closed classifier.
3. **Backend retry redesign** — the verified spool supplies the existing
   seekable/replayable requirement; global retry policy is unchanged.
4. **Ordinary fixed-body hash verification** — hexadecimal
   `X-Amz-Content-Sha256` and `UNSIGNED-PAYLOAD` remain non-streaming paths.
   This issue's signed-payload target is the complete SigV4 streaming payload
   chain, including signed trailers.
5. **Configuration knobs for parser limits** — use package constants in this
   focused change; configurable limits can be added separately if operational
   evidence requires them.

## 3. Target Interface / Semantics / Behaviour

### 3.1 Closed mode classification

```go
type streamingPayloadMode uint8

const (
    streamingNone streamingPayloadMode = iota
    streamingSignedPayload
    streamingSignedPayloadTrailer
    streamingUnsignedPayloadTrailer
)

func classifyStreamingPayloadMode(value string) (streamingPayloadMode, error)
```

| Exact `X-Amz-Content-Sha256` value | Classification | Chunk HMAC | Trailers |
|---|---|---:|---|
| `STREAMING-AWS4-HMAC-SHA256-PAYLOAD` | `streamingSignedPayload` | Required, including zero chunk | Forbidden |
| `STREAMING-AWS4-HMAC-SHA256-PAYLOAD-TRAILER` | `streamingSignedPayloadTrailer` | Required, including zero chunk | Declared set plus `x-amz-trailer-signature`; signature and checksum verified |
| `STREAMING-UNSIGNED-PAYLOAD-TRAILER` | `streamingUnsignedPayloadTrailer` | Forbidden | Declared set; checksum verified, strict framing |
| Empty, 64 lowercase hexadecimal characters, or `UNSIGNED-PAYLOAD` | `streamingNone` | N/A | Existing non-streaming path |
| Any other value, including every other `STREAMING-*` token | Error | N/A | Rejected before body/backend access |

Classification is case-sensitive because these are protocol constants. A
streaming token is valid only for SigV4 header authentication, only when
`Content-Encoding` contains the `aws-chunked` coding, and only with one valid
non-negative decimal `X-Amz-Decoded-Content-Length`. Duplicate singleton
headers, comma-ambiguous values, integer overflow, or a conflicting coding are
invalid. This closed matrix prevents accidental support from being created by
a prefix check.

### 3.2 Verified signing context

```go
// V4SigningContext contains verified request-scoped inputs for SigV4 body
// verification.
// Invariants:
//   - constructed only after the seed signature passes hmac.Equal;
//   - owned by one request and never shared concurrently;
//   - signingKey and previousSignature are zeroized exactly once by Close;
//   - Close is nil-safe and idempotent; methods fail after Close;
//   - no field or error formatter exposes key or signature bytes.
type V4SigningContext struct {
    timestamp         string
    credentialScope   string
    signingKey        []byte
    seedSignature     [32]byte
    mode              streamingPayloadMode
}

func ValidateSignatureV4(
    r *http.Request,
    secretKey string,
    clockSkew time.Duration,
) (*V4SigningContext, error)

func (c *V4SigningContext) Close()
```

For non-streaming V4 requests, successful validation may return a context with
`mode == streamingNone`; middleware still defers `Close`. On every parse,
expiry, seed-signature, or mode-classification error, the function zeroizes
temporary derivation buffers and returns `(nil, err)`. `AuthMiddleware` stores
the context on the request only after success and executes `defer ctx.Close()`
around the downstream handler. V2 requests never receive this context.

The return type makes seed verification a construction boundary: code cannot
instantiate an apparently trusted body verifier from unverified request text.
The context remains deliberately concrete and package-private in its fields so
callers cannot replace the previous signature or signing key.

### 3.3 Streaming verifier and spool

```go
const (
    maxAWSChunkHeaderBytes = 8 << 10
    maxAWSTrailerBytes     = 64 << 10
    maxAWSTrailerCount     = 64
)

// verifiedAWSBody is a decoded, fully verified, seekable temporary body.
// Close removes the spool and is idempotent.
type verifiedAWSBody interface {
    io.Reader
    io.Seeker
    io.Closer
    DecodedLength() int64
}

func verifyAndSpoolAWSBody(
    r *http.Request,
    signing *V4SigningContext,
) (verifiedAWSBody, error)
```

The verifier reads incrementally into a restrictive-permission temporary file,
never retaining the full payload in memory. It removes partial files on every
error and rewinds only after all checks pass. The declared decoded length is a
hard upper bound while spooling: decoding one byte beyond it fails immediately;
ending below it returns `IncompleteBody`. The handler defers `Close` and passes
the already verified seekable body to encryption/backend logic.

For each signed chunk, parse exactly:

```text
<1..16 lowercase hex digits>;chunk-signature=<64 lowercase hex digits>\r\n
<exactly chunk-size bytes>\r\n
```

No whitespace, sign, leading `0x`, empty line, duplicate/unknown extension,
bare LF, or extra extension is accepted. Non-final chunks must have size
greater than zero. The final chunk must have size zero and, in signed modes,
must carry a valid signature. The expected signature is:

```text
HMAC-SHA256(signingKey,
  "AWS4-HMAC-SHA256-PAYLOAD\n" +
  timestamp + "\n" + credentialScope + "\n" +
  hex(previousSignature) + "\n" +
  SHA256("") + "\n" + SHA256(chunkData))
```

The seed request signature is `previousSignature` for the first chunk; each
accepted chunk signature becomes the predecessor for the next chunk. Decode
both expected and supplied signatures to fixed 32-byte arrays, compare with
`hmac.Equal`, and update the chain only after a successful comparison. Apply
the same formula to the zero-length final chunk. Never compare hexadecimal
strings directly and never include either signature in an error [1][4].

Unsigned mode uses `<size>\r\n<data>\r\n` and rejects any chunk extension.
All modes enforce the header/trailer bounds before allocation. After the final
terminator/trailers, require physical EOF by reading one byte: any byte,
including CR, LF, or whitespace, is `ErrStreamingTrailingData`.

### 3.4 Trailer contract

Trailer modes require exactly one `X-Amz-Trailer` request header containing a
comma-separated list of lowercase field names. Reject empty names, duplicates,
uppercase/non-token bytes, forbidden framing/auth fields, and more than
`maxAWSTrailerCount`. The received trailer block uses exact
`lowercase-name:value\r\n` lines followed by one empty `\r\n`; its declared
fields must occur exactly once and in the declared set. The aggregate encoded
block must not exceed `maxAWSTrailerBytes`.

Allowed payload trailers are `x-amz-checksum-crc32`,
`x-amz-checksum-crc32c`, `x-amz-checksum-sha1`, and
`x-amz-checksum-sha256`. Decode their canonical base64 values to the exact
digest width and compare the recomputed decoded-payload digest in constant
time. Unknown, undeclared, duplicate, malformed, or mismatching payload
trailers fail closed.

For `STREAMING-AWS4-HMAC-SHA256-PAYLOAD-TRAILER`, require one additional final
`x-amz-trailer-signature` field (not listed as a payload trailer). Canonicalize
the declared payload trailer fields by sorted lowercase name, normalized value,
and a terminating newline. Verify:

```text
HMAC-SHA256(signingKey,
  "AWS4-HMAC-SHA256-TRAILER\n" +
  timestamp + "\n" + credentialScope + "\n" +
  hex(finalZeroChunkSignature) + "\n" +
  SHA256(canonicalTrailerHeaders))
```

The supplied trailer signature is exactly 64 lowercase hexadecimal characters
and is compared as fixed bytes with `hmac.Equal` [2]. The unsigned-trailer mode
does not accept `x-amz-trailer-signature`, but still validates declaration,
syntax, bounds, checksums, empty-line termination, EOF, and decoded length.

### 3.5 Errors and S3 responses

```go
var (
    ErrUnsupportedStreamingMode = errors.New("unsupported SigV4 streaming payload mode")
    ErrStreamingFraming         = errors.New("invalid AWS-chunked framing")
    ErrStreamingLength          = errors.New("decoded payload length mismatch")
    ErrStreamingTrailer         = errors.New("invalid AWS-chunked trailer")
    ErrStreamingTrailingData    = errors.New("data follows AWS-chunked message")
)
```

| Failure | HTTP | S3 code | Exact client message |
|---|---:|---|---|
| Unknown/unsupported streaming mode or invalid mode/header combination | 400 | `InvalidRequest` | `The streaming payload mode is not supported.` |
| Missing/invalid/oversized chunk header, extension, CRLF, trailer syntax, trailer declaration, or trailing bytes | 400 | `InvalidRequest` | `The AWS-chunked request body is invalid.` |
| Decoded bytes fewer than declared | 400 | `IncompleteBody` | `You did not provide the number of bytes specified by the Content-Length HTTP header.` |
| Decoded bytes exceed declared | 400 | `InvalidRequest` | `The decoded content length does not match x-amz-decoded-content-length.` |
| Data-chunk, zero-chunk, trailer-signature, or checksum mismatch | 403 | `SignatureDoesNotMatch` | `The request signature we calculated does not match the signature you provided. Check your key and signing method.` |
| Temporary spool create/write/seek failure | 500 | `InternalError` | `We encountered an internal error. Please try again.` |

Internal errors may wrap sentinels for logs but must not contain key material,
expected signatures, supplied signatures, chunk data, or trailer values. Body
errors are written by one `writeStreamingPayloadError` classifier so PutObject
and UploadPart cannot drift.

### 3.6 Handler and atomicity contract

`handlePutObject` and `handleUploadPart` call the closed classifier and
`verifyAndSpoolAWSBody` before encryption, backend lookup/mutation, cache
invalidation, audit-success events, or MPU-state mutation. Only a fully
verified and rewound spool enters the current encryption path. The decoded
spool length, not an unchecked header, becomes `originalBytes`, `plainLen`, and
the source for backend content-length calculations.

No invalid body may call `s3.Client.PutObject` or `s3.Client.UploadPart`.
UploadPart must not call `StateStore.AppendPart` until the verified spool has
been consumed and the backend part succeeds. A rejected UploadPart leaves an
existing MPU record byte-for-byte unchanged; it does not create, append,
refresh TTL, complete, or abort MPU state. This preflight spool is intentional:
it gives a testable atomic boundary independent of whether a backend happens
to roll back a streaming HTTP request.

### 3.7 Safe staged rollout

If complete signed-trailer interoperability cannot be proven in the first
merge, stage the release without weakening the final contract:

1. Merge the closed classifier, context lifecycle, strict parser, signed
   payload chain, unsigned-trailer checks, atomic spool, and tests.
2. Keep `STREAMING-AWS4-HMAC-SHA256-PAYLOAD-TRAILER` classified but return the
   exact unsupported-mode `InvalidRequest` before body/backend access.
3. Enable that mode only in the same release/PR that lands official-style
   signed-trailer vectors, trailer HMAC/checksum verification, handler tests,
   and documentation.

The completed V1.0-SEC-41 target is not the staged subset: both
`STREAMING-AWS4-HMAC-SHA256-PAYLOAD` and
`STREAMING-AWS4-HMAC-SHA256-PAYLOAD-TRAILER` must perform full signed payload
verification. There is no compatibility fallback that strips unverified
signatures.

### Tier 2 conformance

The mandatory provider matrix uses the `conformance` tier, not an ad hoc
`integration` tag. Tests use independent signing code, register in
`test/conformance/suite_test.go`, and do not branch on provider names. Docker
absence is a named skip. Positive and negative object tests are a pair: a
negative test alone cannot prove the generated signature was initially valid.

| Function | Suite registration | Capability | Assertion |
|---|---|---:|---|
| `testSEC41_SigV4Streaming_PutObjectRoundTrip` | `SEC41_SigV4Streaming_PutObjectRoundTrip` | `0` | Multi-chunk signed payload and signed zero chunk store exact decoded bytes. |
| `testSEC41_SigV4Streaming_TamperedPutObjectRejectedWithoutObject` | `SEC41_SigV4Streaming_TamperedPutObjectRejectedWithoutObject` | `0` | Post-signing mutation receives the specified error and leaves no target object. |
| `testSEC41_SigV4Streaming_UploadPartRoundTrip` | `SEC41_SigV4Streaming_UploadPartRoundTrip` | `provider.CapMultipartUpload` | Signed streaming part completes to exact plaintext. |
| `testSEC41_SigV4Streaming_TamperedUploadPartRejected` | `SEC41_SigV4Streaming_TamperedUploadPartRejected` | `provider.CapMultipartUpload` | Tampered part is rejected and cannot be completed or observed in ListParts. |
| `testSEC41_SigV4Streaming_SignedTrailerPutRoundTrip` | `SEC41_SigV4Streaming_SignedTrailerPutRoundTrip` | `0` | Independently signed trailer/checksum request stores exact plaintext. |

Exhaustive framing variants, official fixed vectors, constant-time internals,
chain-state mutations, signing-key zeroization, spool permissions/removal, and
backend-call ordering remain Tier 1. Tier 2 proves only the externally visible
cross-provider commit/no-commit contract.

Handler tests must use spies that fail the test immediately if a mutation method
is called before verification returns. MPU tests compare state contents and TTL
before/after rejection. Golden vectors use fixed timestamps and public sample
keys; no environment credentials or live AWS account are required.

## 7. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| A parser variation accepts ambiguous framing interpreted differently elsewhere | Exact byte grammar, no `TrimSpace`, exact CRLF, one extension shape, bounded lines, fuzzing, and official vectors |
| A late invalid chunk reaches a backend before rejection | Verify and spool the complete body before any backend/state mutation; backend/state spies make this a release gate |
| Signing-key lifetime expands when returned from seed validation | Unexported fields, request ownership, deferred idempotent `Close`, zeroization on every construction/error/close path, and lifecycle tests |
| Trailer canonicalization differs from AWS | Implement the documented sorted lowercase canonical form and gate support on the official-style signed-trailer vector [2] |
| Signed-trailer work is incomplete at merge time | Keep the exact token classified but fail closed with the documented `InvalidRequest`; never decode it unsigned; enable only with complete tests |
| Temporary spooling increases disk pressure or leaves plaintext files | Mode 0600 files, immediate unlink-on-error/close, context cancellation, decoded-length hard bound, operator documentation, and cleanup tests |
| Existing clients rely on permissive fake signatures or malformed frames | Treat rejection as the intended security change, publish the closed compatibility matrix, and validate real AWS SDK/CLI-style traffic |
| Error details expose signatures or payload data | Central fixed-message classifier; tests search XML/log-captured fields for expected/supplied signatures and trailer/body values |
| Declared length is used despite differing decoded bytes | Treat it only as a hard bound; derive all downstream lengths from the successfully verified spool |
| UploadPart rejection mutates Valkey TTL/state despite no part commit | Move verification before state mutation and snapshot contents plus TTL in atomicity tests |

## 8. Definition of Done

- [ ] `classifyStreamingPayloadMode` accepts exactly the three streaming tokens
      in §3.1; every other `STREAMING-*` value receives the exact fail-closed
      response in §3.5 before body/backend access.
- [ ] `ValidateSignatureV4` returns a `V4SigningContext` only after successful
      constant-time seed verification, and no failed request exposes a context.
- [ ] Every signed data chunk and final zero chunk is chained from the prior
      accepted signature and compared as fixed bytes with `hmac.Equal`.
- [ ] Signed-trailer mode authenticates canonical declared trailers and verifies
      supported payload checksums; unsigned-trailer mode applies all non-HMAC
      framing, declaration, checksum, length, EOF, and limit checks.
- [ ] Parsing requires exact CRLF, bounded chunk headers/trailer bytes/count,
      exact decoded length, one final zero chunk, physical EOF, and no trailing
      byte.

      signatures are zeroized on success, error, close, cancellation, and panic
      cleanup paths.
- [ ] Invalid PutObject bodies produce zero backend `PutObject` calls and no
      cache or success-state mutation.
- [ ] Invalid UploadPart bodies produce zero backend `UploadPart` calls and no
      MPU create, append, TTL refresh, complete, or abort mutation.
- [ ] All failures return the exact HTTP/S3 code/message table in §3.5 without
      exposing signatures, keys, decoded data, or trailer values.
- [ ] Official AWS-style signed-payload and signed-trailer vectors pass, and a
      one-byte mutation in every authenticated component fails.

      payload and signed-trailer verification.
- [ ] `SECURITY.md`, `docs/SDK_COMPATIBILITY.md`, and `CHANGELOG.md` describe
