# V1.0-AUTH-2 — Per-Credential Bucket Scoping and Authorization — Implementation Plan

## 1. Context & Current State

V1.0-AUTH-1 made authentication mandatory, but authorization remains flat.
`GatewayCredential` contains only key material and a label
(`internal/config/config.go:701`); `CredentialStore.Lookup` returns only a
secret and label (`internal/api/credential_store.go:9`). `AuthMiddleware`
attaches only that label after signature validation
(`internal/api/auth_middleware.go:107`). Any valid credential can therefore
use every operation against every bucket visible to the shared backend identity.

`PROXIED_BUCKET` is one global exact-name filter, not tenant authorization. Its
middleware parses the first path segment and copy-source header
(`internal/middleware/bucket_validation.go:11`) and currently rejects root
ListBuckets. Per-credential scope must intersect with, never replace or widen,
this deployment-wide restriction.

`handleListBuckets` currently forwards the complete backend inventory
(`internal/api/handlers.go:5401`). CopyObject reaches source objects through the
shared backend client (`internal/api/handlers.go:4870`). UploadPartCopy even
states that backend access enforces caller authorization
(`internal/api/upload_part_copy.go:89`), which is no longer true because callers
do not have distinct backend identities. Both copy endpoints need explicit
source-read and destination-write checks before backend access.

The store is also startup-only (`cmd/server/main.go:749`). Config reload accepts
credential changes but `ConfigChangeApplier` has no store reference
(`cmd/server/main.go:47`), and only the main config file is watched
(`internal/config/config.go:2312`). The objective is a least-privilege,
auditable, atomically reloadable credential policy [1][2]. ADR 0012 remains the
foundation for separating gateway and backend credentials
(`docs/adr/0012-unified-credential-store.md:47`).

## 2. Design Goals & Non-Goals

### Goals

1. Exact names and constrained trailing-`*` prefixes scope each credential.
2. Object access is `ro` or `rw`; bucket create/delete are explicit grants.
3. Authorization runs after authentication and before any backend-capable code.
4. CopyObject and UploadPartCopy authorize source and destination independently.
5. ListBuckets exposes only the effective authorized inventory.
6. Omitted policy fields preserve existing unrestricted/read-write behavior.
7. Explicit empty bucket scope denies every bucket.
8. Complete credential snapshots hot-reload atomically and are auditable.

### Non-Goals

1. Object-key or prefix authorization; scope is bucket-only.
2. AWS IAM policy language or deny-rule evaluation.
3. Arbitrary glob syntax; only exact names and one trailing `*` are accepted.
4. CreateBucket execution; V1.0-S3-5 consumes this issue's authorization model.
5. Forwarding gateway credentials to the backend; ADR 0012 remains unchanged.

## 3. Target Interface / Semantics / Behaviour

### Configuration contract

```yaml
auth:
  credentials:
    - access_key: service-a
      secret_key_env: SERVICE_A_SECRET
      label: service-a
      buckets: [app-service-a, shared-*]
      permissions: ro
      bucket_permissions: [create, delete]
```

| Field | Omitted | Explicit empty | Accepted values |
|---|---|---|---|
| `buckets` | unrestricted | deny all | exact name or non-empty prefix plus one trailing `*` |
| `permissions` | `rw` | invalid | `ro`, `rw` |
| `bucket_permissions` | none | none | `create`, `delete` |

Environment equivalents are `GW_CRED_N_BUCKETS`,
`GW_CRED_N_PERMISSIONS`, and `GW_CRED_N_BUCKET_PERMISSIONS`.
`GW_CRED_N_BUCKETS` uses `os.LookupEnv`: absent means unrestricted; present
empty means deny all. Reject `*`, `*foo`, `foo*bar`, multiple stars,
whitespace-only entries, duplicate access keys, and unknown/duplicate grants.
Do not normalize bucket-name case.

Rationale: nil-versus-empty preserves deployed credentials while supporting an
intentional deny-all policy. The constrained prefix grammar supports `app-*`
without path-glob ambiguity.

```go
type ObjectPermission string
const (
    ObjectPermissionReadOnly  ObjectPermission = "ro"
    ObjectPermissionReadWrite ObjectPermission = "rw"
)

type BucketPermission string
const (
    BucketPermissionCreate BucketPermission = "create"
    BucketPermissionDelete BucketPermission = "delete"
)

type Credential struct {
    AccessKey string
    SecretKey string
    Label     string
    Policy    AuthorizationPolicy
}

// CredentialStore invariants:
//   - lookups and replacements are safe for concurrent use;
//   - callers cannot mutate store-owned policy data;
//   - a replacement is fully validated before one atomic publication;
//   - failed replacement preserves the previous snapshot;
//   - secrets are never logged.
type CredentialStore interface {
    Lookup(accessKey string) (Credential, error)
    Replace(credentials []config.GatewayCredential) error
}
```

The implementation publishes an immutable `credentialSnapshot` through
`atomic.Pointer`. A request keeps the principal snapshot authenticated at its
start. `ResolvedCredentials` deep-copies authorization slices.

### Effective scope and operations

```text
effective scope = credential bucket scope INTERSECT optional PROXIED_BUCKET
```

| Operation class | Required grant | Additional requirement |
|---|---|---|
| GET/HEAD/list object or subresource | `ro` or `rw` | target bucket in scope |
| Object, multipart, or subresource mutation | `rw` | target bucket in scope |
| CopyObject / UploadPartCopy | destination `rw` | source in scope and readable |
| CreateBucket | `bucket_permissions:create` | target in scope; execution in S3-5 |
| DeleteBucket | `bucket_permissions:delete` | target in scope |
| ListBuckets | `ro` or `rw` | filter output to effective scope |

Unknown S3 operations fail closed. System endpoints retain exact-match bypasses.
`rw` never implies bucket creation or deletion.

Denial returns HTTP 403 S3 XML with `Code=AccessDenied`, `Message=Access
Denied`, and request path as `Resource`, using a per-request clone of
`ErrAccessDenied` (`internal/api/errors.go:205`). It emits
`auth.authorization_denied` with bounded reason (`bucket_scope`, `read_only`,
`bucket_create`, `bucket_delete`, `unknown_operation`) and no secret material.

Restricted ListBuckets parses a successful `ListAllMyBucketsResult`, preserves
owner, namespace and creation dates, and filters `<Bucket>` entries. Deny-all
returns HTTP 200 with empty `<Buckets>`. Backend errors pass through. Malformed
successful XML returns 502 and never exposes the unfiltered body.

## 4. Work Breakdown

### Phase A — Credential policy schema

- **A1 — edit `internal/config/config.go`:** add typed scope and permissions;
  validate patterns, duplicates, defaults, and nil/empty semantics.
- **A2 — edit `internal/config/config.go`:** parse indexed authorization env
  variables and label; validate the final merged YAML/env/file set.
- **A3 — edit `internal/config/config_test.go`:** cover all schema, environment,
  file, duplicate, wildcard, and deep-copy cases.

### Phase B — Immutable store and reload

- **B1 — edit `internal/api/credential_store.go`:** return `Credential`, compile
  bucket matchers, and add atomic `Replace`.
- **B2 — edit `internal/api/credential_store_test.go`:** test matching,
  defensive immutability, replacement rollback, and concurrency.
- **B3 — edit `cmd/server/main.go`:** give `ConfigChangeApplier` the store,
  replace changed credentials atomically, and zero transient secrets.
- **B4 — edit `internal/config/config.go`:** watch main config and
  `AUTH_CREDENTIALS_FILE`, including write/create/rename; SIGHUP rereads both.
- **B5 — edit `internal/config/config_reloader_test.go`; new
  `cmd/server/main_test.go`:** verify add/remove/scope reload and rollback.

### Phase C — Authorization boundary

- **C1 — new `internal/api/authorization.go`:** classify route/query/header
  combinations, intersect global scope, expose `CredentialFromContext`, and
  deny before calling the wrapped handler.
- **C2 — new `internal/api/authorization_test.go`:** cover every operation
  class, unknown routes, system endpoints, scope forms, and zero downstream calls.
- **C3 — edit `internal/api/auth_middleware.go`:** attach the authenticated
  `Credential`; preserve `CredentialLabelFromContext`.
- **C4 — edit `cmd/server/main.go`:** install authorization immediately inside
  authentication and outside all backend-capable middleware/handlers.
- **C5 — edit `internal/audit/audit.go`:** add authorization-denial event type.
- **C6 — edit `internal/api/errors.go`:** add request-safe AccessDenied writer.

### Phase D — Copy and inventory isolation

- **D1 — edit `internal/api/handlers.go`:** authorize CopyObject source and
  destination before client acquisition or backend reads.
- **D2 — edit `internal/api/upload_part_copy.go`:** parse and authorize source
  before backend client use; correct the stale backend-authorization invariant.
- **D3 — edit `internal/api/handlers.go`:** implement bounded ListBuckets XML
  filtering and global-scope intersection.
- **D4 — edit `internal/middleware/bucket_validation.go`:** allow ListBuckets
  through for filtering and share source parsing/error semantics.
- **D5 — edit handler and copy tests:** assert every denial makes zero backend calls.

### Phase E — Deployment and documentation

- **E1 — edit Helm values, schema, deployment, and auth chart tests:** expose
  scopes and permission enums while preserving omitted versus empty buckets.
- **E2 — edit `config.yaml.example`, `README.md`, `docs/DEPLOYMENT.md`,
  `docs/ARCHITECTURE.md`, `docs/S3_CLI_TOOLS.md`, `docs/arc42/arc42.md`, and
  chart README:** document migration, reload, wildcard, and least privilege.
- **E3 — new `docs/adr/0016-per-credential-authorization.md`:** record the
  policy grammar, operation matrix, global intersection, filtering, and reload.
- **E4 — edit `CHANGELOG.md`:** add V1.0-AUTH-2 under Unreleased.

## 7. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Existing clients are locked out | Omitted scope and permission preserve unrestricted `rw`; test upgrades. |
| Empty scope collapses to omitted | Use `LookupEnv`; chart tests distinguish absent and present-empty. |
| Wildcard grants unrelated buckets | Accept only one trailing `*` with non-empty prefix; reject `*`. |
| Method-only classifier permits mutation | Classify route/query/header semantics; unknown operations fail closed. |
| Copy reads unauthorized data | Authorize parsed source and destination before all backend paths. |
| ListBuckets leaks on malformed XML | Never return unfiltered successful content after parse failure. |
| Reload publishes partial policy | Build, validate, then atomically swap one complete snapshot. |
| Mutable request policy affects other clients | Deep-copy and expose immutable principal values. |
| `PROXIED_BUCKET` widens scope | Compute intersection and test unrestricted, overlapping, and disjoint cases. |

## 8. Definition of Done

- [x] Per `docs/issues/v1.0-issues.md:20`, exact and trailing-prefix scopes work.
- [x] Omitted buckets are unrestricted; explicit empty buckets deny all.
- [x] Omitted object permission is `rw`; `ro` blocks every mutation.
- [x] `rw` grants neither bucket create nor bucket delete.
- [x] Unknown operations fail closed before backend access.
- [x] CopyObject and UploadPartCopy authorize source read and destination write.
- [x] ListBuckets filters effective scope and fails closed on malformed XML.
- [x] `PROXIED_BUCKET` only narrows credential scope and permits filtered ListBuckets.
- [x] Every denial returns S3 AccessDenied and emits a bounded audit event.
- [x] Credential changes hot-reload atomically; invalid reload retains old state.
- [x] No authorization denial test observes a backend call.
- [x] New critical code has at least 85% statement coverage.
- [x] ADR, examples, Helm schema/tests, architecture docs, and CHANGELOG are updated.
- [x] Race tests, `go vet`, FIPS vet, Helm tests, and incremental lint are clean.

## 10. Follow-ups / Out-of-scope items surfaced during planning

- Object-key prefix policies may be considered separately if bucket isolation
  proves insufficient; they must not be added to this policy grammar implicitly.
- V1.0-S3-5 implements authorized CreateBucket passthrough after this plan lands.
- Per-credential rate limits and metrics are separate concerns; do not use access
  keys as Prometheus labels.
