### Summary
The reporter of GH-283 receives `BadGateway` from root `aws s3 ls` when
`GW_CRED_0_PERMISSIONS=rw` or
`GW_CRED_0_BUCKET_PERMISSIONS=create,delete` is explicitly configured, both
together and individually. AWS CLI 2.34.32 reports:

```text
An error occurred (BadGateway) when calling the ListBuckets operation
(reached max retries: 2): The upstream S3 backend returned an error.
```

Direct `ListBuckets` access to RustFS succeeds. The reporter intends the gateway
to connect over HTTP to the internal `rustfs:9000` endpoint. That endpoint is
scheme-less, so every backend request path must apply the `BACKEND_USE_SSL=false`
normalization fixed for the primary backend clients by GH-284.

Object permissions and bucket lifecycle grants are independent. Explicit `rw`
must permit ListBuckets just as the omitted default does, while `create` and
`delete` must affect only their corresponding bucket lifecycle operations.
Diagnose and fix the configuration-dependent forwarding failure without
weakening credential authorization or changing those permission meanings.

### Current Analysis
- Environment loading stores `GW_CRED_<n>_PERMISSIONS` and
  `GW_CRED_<n>_BUCKET_PERMISSIONS` in separate credential fields.
- Credential validation accepts `rw`, `create`, and `delete`.
- ListBuckets authorization accepts both `ro` and `rw` and does not inspect
  bucket lifecycle grants.
- The reported response text is emitted when `forwardToBackend` returns a
  request or transport error. A backend non-2xx response is proxied, and an
  invalid successful response produces a different 502 message.
- The ListBuckets handler currently discards the wrapped forwarding error, so
  the supplied access log cannot identify whether request construction,
  signing, endpoint selection, or transport failed.
- An absent `GW_CRED_<n>_BUCKETS` value means unrestricted scope. An explicitly
  present empty value means deny-all and should return HTTP 200 with an empty
  bucket list after filtering, not 502.

### Implementation Guide
- [x] Reproduce the failure through the real indexed environment loader, not
      only by constructing `GatewayCredential` values directly in tests.
- [x] Capture the effective backend endpoint and safely log the wrapped
      `forwardToBackend` error for ListBuckets without logging credentials,
      signatures, secrets, or sensitive query values.
- [x] Identify and fix the configuration interaction that makes explicit valid
      permission values alter or break backend ListBuckets forwarding.
- [x] Preserve the default and explicit permission contracts: omitted object
      permission defaults to `rw`; explicit `ro` and `rw` authorize
      ListBuckets; lifecycle grants do not authorize or deny ListBuckets.
- [x] Preserve bucket-scope filtering: absent scope is unrestricted and an
      explicitly empty scope is deny-all.
- [x] Continue proxying backend S3 error responses instead of replacing them
      with the gateway's transport-level `BadGateway` response.
- [x] Document the indexed environment variables and the independence of
      object, lifecycle, and bucket-scope controls.
