## [V1.0-OBS-2] Per-Bucket Request and Client Traffic Metrics ✅ DONE
- Owner: Observability / API
- Priority: P1
- Status: **✅ VERIFIED COMPLETE**
- Labels: `milestone:v1.0`, `area:observability`, `area:api`, `area:helm`
- Plan: `docs/plans/V1.0-OBS-2-plan.md`
- GitHub Issue: https://github.com/cloud37/s3-encryption-gateway/issues/230

### Summary
Add stable per-bucket semantic request/status and client-visible plaintext byte
metrics. Preserve all existing Prometheus metric names and label schemas;
`s3_operations_total{operation,bucket}` and related semantic metrics already
exist and remain supported. Instrument actual bytes consumed from and written
to clients, including decoded AWS streaming uploads and partial/range responses.

### Metrics contract
- `s3_client_requests_total{operation,bucket,status_code}` records every completed S3 route once.
- `s3_client_bytes_total{bucket,direction}` records actual plaintext client traffic for `in|out`.
- `METRICS_ENABLE_BUCKET_LABEL=false` collapses the new metrics to `bucket="*"`.
- No object key, upload ID, access key, path, or arbitrary error text becomes a label.

### Definition of Done
- [x] Existing metric label schemas remain unchanged.
- [x] New request metrics cover successful, local-error, and backend-error responses exactly once.
- [x] New byte metrics count actual client-visible bytes without retry double-counting.
- [x] Passthrough operations receive semantic operation/error instrumentation.
- [x] Grafana dashboards, Helm descriptions/tests, observability docs, and cardinality tests are updated.
