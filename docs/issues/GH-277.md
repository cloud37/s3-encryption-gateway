## [GH-277] Publish Helm chart in a signed OCI registry
- Owner: Release Engineering / Helm
- Priority: P2
- Status: Planned
- Labels: `area:helm`, `area:release`, `area:supply-chain`
- Plan: `docs/plans/GH-277-plan.md`
- Source: <https://github.com/cloud37/s3-encryption-gateway/issues/277>

### Summary
Publish each Helm chart release as a signed OCI artifact in GHCR in addition to,
not instead of, the existing GitHub Pages Helm repository. The package must be
associated with this repository and use the existing keyless Sigstore/cosign
release identity.

The intended install reference is
`oci://ghcr.io/cloud37/s3-encryption-gateway --version <version>`. The classic
`helm repo add s3-encryption-gateway https://cloud37.github.io/s3-encryption-gateway`
workflow remains supported.

### Affected
- `.github/workflows/helm.yml` — package, publish, sign, and verify the OCI chart.
- `helm/s3-encryption-gateway/README.md` — document OCI installation and verification.
- `CHANGELOG.md` — announce the additional signed distribution channel.

### Implementation Guide
- [ ] Grant the release job only the package and OIDC permissions it requires.
- [ ] Authenticate Helm to GHCR with the repository `GITHUB_TOKEN`.
- [ ] Package once, push to `oci://ghcr.io/cloud37`, and sign the resulting chart reference by digest.
- [ ] Verify the keyless signature against this repository's release workflow identity.
- [ ] Preserve the existing chart-releaser/GitHub Pages publication.

### Tests
- [ ] Pull/show the published OCI chart by version and verify chart metadata.
- [ ] Verify its cosign signature using issuer and workflow identity constraints.
- [ ] Keep chart lint, template, packaging, unit, and conformance gates green.

### Definition of Done
- [ ] A release publishes the same chart version through GitHub Pages and GHCR.
- [ ] The GHCR artifact is signed by the repository's GitHub Actions OIDC identity.
- [ ] Documentation includes versioned install, digest-pinned install, and signature verification commands.
- [ ] Existing classic Helm repository consumers are unaffected.
