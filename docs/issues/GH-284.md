## [GH-284] Honor BACKEND_USE_SSL=false for scheme-less endpoints ✅ DONE

### Summary
`BACKEND_USE_SSL=false` is not loaded from the environment. A scheme-less
`BACKEND_ENDPOINT=rustfs:9000` therefore keeps the default `use_ssl: true` and
is normalized to HTTPS. Explicit `http://` currently works and must continue to
take precedence over `use_ssl`.

Fix environment parsing and make both backend client paths apply one scheme
contract: an explicit `http://` or `https://` scheme wins; otherwise `use_ssl`
selects HTTPS when true and HTTP when false.

### Affected
- `internal/config/config.go` — load `BACKEND_USE_SSL` as a strict boolean override.
- `internal/config/config_test.go` — cover true, false, invalid, YAML, and default behavior.
- `internal/s3/client.go` — normalize scheme-less SDK endpoints from `UseSSL`.
- `internal/s3/client_test.go` — cover endpoint precedence and scheme selection.
- `internal/s3/proxy_client.go` — use the same endpoint normalization contract.
- `internal/s3/proxy_client_test.go` — regress proxy behavior.
- `CHANGELOG.md` — record the fix.

### Implementation Guide
- [x] Parse `BACKEND_USE_SSL` with `strconv.ParseBool`; reject invalid values.
- [x] Preserve the secure default `use_ssl: true` when no override exists.
- [x] Make explicit endpoint schemes authoritative.
- [x] Apply identical behavior to SDK and proxy clients.

### Tests
- [x] Environment `false` overrides the default and YAML `true`.
- [x] Environment `true` overrides YAML `false`.
- [x] Invalid values fail configuration loading.
- [x] Scheme-less endpoints use the configured scheme in both client paths.
- [x] Explicit schemes remain unchanged even when they disagree with `use_ssl`.

### Definition of Done
- [x] `BACKEND_ENDPOINT=rustfs:9000 BACKEND_USE_SSL=false` uses `http://rustfs:9000`.
- [x] Unset `BACKEND_USE_SSL` retains the secure HTTPS default.

- [x] Unit and conformance suites pass.
