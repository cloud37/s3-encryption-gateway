### Summary
Add a preferred custom-CA mechanism and an explicit diagnostic/development
escape hatch for backend TLS verification. The YAML contract is
`backend.tls.ca_file` and `backend.tls.insecure_skip_verify`; environment
equivalents are `BACKEND_TLS_CA_FILE` and
`BACKEND_TLS_INSECURE_SKIP_VERIFY`.

Custom CA trust retains HTTPS server identity verification and is the preferred
solution for private PKI. Insecure skip-verify retains HTTPS encryption but
disables certificate and hostname verification; it must default false and emit
a prominent startup warning when enabled. Plain HTTP remains controlled by
`backend.use_ssl` / `BACKEND_USE_SSL` and is a distinct setting.

### Implementation Guide
- [x] Append a PEM CA file to a clone of the system root pool.
- [x] Fail startup/client construction when a configured CA file is unreadable or contains no certificates.
- [x] Apply one TLS transport builder to SDK and proxy backend paths.
- [x] Never change the default verification behavior.
- [x] Warn without logging certificate content when insecure mode is enabled.

### Tests
- [x] A private-CA TLS backend fails without the CA and succeeds with it.
- [x] Insecure mode succeeds against an otherwise untrusted certificate.
- [x] Malformed/missing CA files fail closed.
- [x] Helm renders direct values and valueFrom references.
- [x] Unit and conformance suites pass.

- [x] Insecure skip-verify is explicit, false by default, and visibly warned.
- [x] Plain HTTP and TLS verification controls remain semantically separate.
